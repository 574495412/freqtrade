## 1. 目标、边界与先后顺序

目标是建立能够被复现、被证伪、包含浮动损益和成本的研发流程，再判断新增因子或风控是否带来增量价值。当前没有可以承诺的最优策略或收益率。先完成 P0 可信度和风险合同，再做 P1 固定基线；通过明确门槛后才进入 P2/P3 自研。本次用户随后确认：路线图提交后继续实施 P0/P1；P2 以后仅列路线，不自动扩展搜索。

首轮具体交付：①运行与历史证据台账；②隔离研究环境的依赖及事件账本核验；③账户浮动权益风险状态机的离线实现/故障测试，明确尚未接入运行盘；④最多四类原版/简单控制的同口径复现；⑤通过、失败、阻塞三种结果及下一步决定。P0 不要求为了运行实验而假装补齐不存在的事件数据。

首轮非目标：提高杠杆、增加币池、海量 hyperopt、机器学习寻优、安装第二个交易执行框架、补造订单簿/资金费/基差、开户或实盘。原运行盘 `deploy/` 文件、进程、信号、配置、密钥、数据库均不改；不创建 `freqtrade-deploy`，不使用 Vibe-Trading 承载交易执行，不向企业微信发研究消息。新研究使用本工程内独立输出目录与账本，绝不把原版历史收益沿用给新风控版。

用户资金合同：现货、合约分别最多初始 1000 USDT；各自权益降至 500 USDT 时停止开仓并尽可能平仓。这是最大初始损失容忍线，既非日常建议止损，也非成交损失上界。研究日常阈值要明显早于该线；不跨账户借用盈余抵消触发，不通过充值或重启重置损失。

## 5. 统一评估合同与试验预算

### 5.1 资本、成本和账本

每个市场/候选独立1000 USDT，禁止共享资金；不复利汇总不同起点账户。现货只多，合约isolated 1x，杠杆覆盖、precision、最低名义额、撮合规则和资金费时刻写入run manifest。B2/B3固定当前36/40币列表和顺序（并列信号按列表顺序），不按事后收益删币。保留动态资格缺口。

成本不搜索：现货基准10+3=13bps/边，压力10+10=20bps/边；合约5+3=8bps/边，压力5+10=15bps/边，均另计资金费。这里只是冻结代理，不声称真实账户费率。若代理全部折进fee参数，账本不得再扣一遍滑点；更真实的改价执行模型须新版本整账重跑。真实费用/盘口证据到位前不得晋级可执行性。

现货权益 `E=cash+Σqty*price−预计退出费用`，cash含历史已收费用；合约 `E=wallet_balance(含已实现损益/已收费用/已结算资金费)+Σ未实现mark PnL−未记账应计资金费−预计退出费用`，占用保证金仍是资产，不再加/减一次。挂单占用影响可用资金与未来敞口，不直接把权益变少。分开保存原生值与保守清算估值；禁止把 `wallets.get_total(stake_currency)`、平仓收益或partial exits直接当MTM。应计与已结算资金费只扣一次。

主报告至少：净收益、5m标记最大回撤及回撤持续期、最差日/周、日收益ES95、每日NAV Sharpe（365日、rf=0、ddof=1）、Sortino、Calmar、换手/费用/资金费、时间及方向敞口、单币/单事件贡献、持仓年龄/DCA/期末未平仓、容量约束与成本压力。缺失/零分母记null；cash零波动Sharpe不可写无穷大。合约缺5m mark只能标条件参考，不能宣称通过标记回撤门槛。每个完整UTC日含空仓日，停止策略后现金日也保留；日收益基于相邻日末净值，不挑有交易日。

期末强制平仓结果与未平仓清算估值分列；forced exit不算自然完成的持仓，不把子订单/分批止盈当独立交易。历史单币和极端事件剔除只做固定敏感性展示，不再据此调阈值。每个基线报告最低费用下限、基准、压力的适用范围；首轮仅跑已注册两成本情景，不临时增加低成本救活策略。

- P0：至多8次新增诊断命令，优先复用已保存24个切片；单条超时/资源失败记录后最多2次技术重试，不增加策略参数。风险状态机的边界/故障单元检查不算经济试验，但单独记数。Recursive固定BTC/ETH/ADA、现货/合约、20261001–20261101、startup=[199,499,799,999]，最多6条；另2条预算用于既有lookahead告警定位，不看结果后换窗口。

- P2（未授权执行）：F1/F2各1个参数版本×2市场×4折×2成本=32个账户；固定cash/B2受限控制另32个；四配置另各跑两市场×两成本的连续L窗16个，共80。不得借空预算引入F3/F4。
- P3（未授权执行）：最多4个新版本（纯风控、风控+F1、风控+F2、两者组合），×2市场×4折×2成本=64个账户；四配置另各跑两市场×两成本的连续L窗16个，共80。通过的成分少于2个时相应删除，不补搜索。ML预算0。
- 单金融worker，单进程RSS上限5.5GiB、单次60分钟；触顶保留partial/failed状态，不自动更改数值精度或减币池。代码修复重试须保持经济定义、追加注册差异。

P1的“通过”是来源、因果、精度、事件、现金可复现，不等于赚钱。数值对账要求确定性事件ID/时刻/方向/数量一致（订单数量按交易所step size），无缺行；现金差<=0.01 USDT、收益差<=0.001个百分点；有差异必须解释为命名的新模型而不是放宽阈值。lookahead未定位、状态路径不同或数据缺失时保留阻塞。原版不通过则不改造其信号；已通过的简单控制可继续作为后续独立因子研发的基础，仍需单独授权P2。

候选晋级经济门槛是工程研究假设：开发4折至少3折基准净收益>0；合并连续账户压力成本净收益>0；5m可信mark MDD<=15%；没有初始500硬线违约；单币正收益贡献<=35%、单日正收益贡献<=25%（分母为各正贡献之和）；主alpha统计量为候选减固定控制的完整UTC日NAV收益差均值（F1对cash，P3增加组件对同市场RD1-only；纯风控只用风险门槛）。对中心化日收益差做长度7日的circular moving-block bootstrap，2000次、seed20261105，单侧p=(1+重抽样均值>=观测均值的次数)/2001。P2新注册家族保守保留4个检验位、P3保留8个，失败/缺失/仅风险位p=1，按Holm step-down在alpha=.05下检验；只有对应alpha检验拒绝零增量才晋级。未校正95%bootstrap区间只作描述，不称Holm校正置信区间。小样本/序列不足/缺mark不强行算p值，记inconclusive。只改善回撤的风险假设用F2的收益保留门槛，不冒充alpha。收益不支配现金/简单控制、费用压力失效、未知事件足以改变决定时停止该候选。

上述Holm仅覆盖当前固定新家族，不覆盖无法恢复次数的旧搜索；P3候选事先筛选仍可能偏乐观，不能代替独立前向。多重试验台账包含旧趋势、反转、资金费、NFI风险、ML家族以及失败/零交易；无法恢复完整旧次数就标 `historical_trial_count=unknown`，不得宣称选择偏差已被数学消除。上述bootstrap只是未来研究方法，不会洗白已看历史；正式独立判断依赖前向留出。失败后不改阈值“救活”，新机制需要新版本、理由与预算。

## 6. 风控设计：原生机制加独立账户状态机

以下是**待实现/离线验证的新研究合同**，不是当前运行事实。

官方原生机制先用，但语义必须准确（固定源码在sources.json，另见[Protections](https://www.freqtrade.io/en/stable/plugins/#protections)）：

| 机制 | 实际语义 | 新研究起点 |
|---|---|---|
| CooldownPeriod | 平仓后锁同pair入场；不全局平仓、不自动撤既有入场单 | stop_duration=60分钟；4h主周期的锁结束仍会向下一4h边界取整 |
| StoplossGuard | 已平仓、特定止损/追踪/交易所止损/强平原因且亏损事件达到次数后锁；自定义derisk不一定计数 | 全局lookback_period=1440分钟、4次，stop_duration=120分钟，required_profit=0 |
| MaxDrawdown | 固定版本默认ratios；显式equity也只用已平仓绝对损益；**不含浮亏**；充足trade_limit且DD严格大于阈值才锁 | equity模式，lookback_period=10080分钟、至少10笔、8%已实现回撤，stop_duration=1440分钟；只是辅助锁 |

保护锁按原生PairLocks持久化并取整到策略主周期的下一根K线；timeframe_detail不会改写原生保护的周期。分钟参数提供一致基础时长，实际恢复时刻仍须按各策略主周期记录。回测必须显式`--enable-protections`才检验新保护；原版控制不偷偷添加它们。官方保护不自动撤单或平仓，DCA有独立执行路径，必须同时控制新trade与正向position adjustment。

新账户权益每5秒尝试更新，价格/账户状态超过15秒不同步就禁止新增风险，回测按事件/5m观测说明时间精度局限。权益必须有当前头寸、待成交入场单、成交/撤单状态、真实可得mark/spot bid、已结算及应计资金费；少一项则未知，不以最后好值继续开仓。

| 层级（高优先级覆盖低层级） | 条件与动作 | 恢复、持久性与验收 |
|---|---|---|
| 账户绝对底线 | 各账户 `E<=500`（含估计退出费）：永久锁新增风险，撤全部入场/DCA余单，保留保护出场，尽可能经原生退出路径清仓 | 持久hard latch；重启不得重置初始1000或解除。须完整对账、原因审查和明确重新授权才恢复；不保证跳空/断网后损失不超50% |
| 账户回撤/日损 | 峰值回撤>=15%或UTC当日初始权益损失>=2%：同上清仓；>=10%先停新增并把gross降至<=30%权益 | 峰值与日初权益持久保存。15%永久复审锁；日损至少到下一UTC日且已flat/无挂单/对账通过才可研究性恢复；10%不自动抄底，需审查解除 |
| 数据/网络/交易所异常 | stale>15s、交易所时钟差>2s、连续3次API错误、未知订单/权益差>0.01：立即锁新增；连接可用时撤入场 | 不盲发重复平仓、不因无报价猜价格；重连先拉订单成交头寸再执行未完成退出。连续5分钟新鲜数据+对账一致且无hard latch才解除技术锁 |
| 总敞口/相关性 | 新版gross<=60%权益，净敞口绝对值<=60%，单币<=10%，最多6笔；最近30天小时收益相关性>=0.7连通簇gross<=30% | 用过去数据每日计算；缺相关数据按同簇保守处理；计入未成交入场余量。上限不因资金减少而扩大；超限只减仓 |
| 单笔/杠杆 | 1x isolated；每笔目标损失<=0.5%权益，固定5%价格止损起步；stake<=min(0.005E/(0.05+双边成本),0.10E,剩余总/簇预算) | 止损、precision、min notional都要验证；不足最小名义额跳过，不为了凑订单放大风险。5%为工程起点，不是最优结论 |
| DCA | 首个新风控版DCA=0；原版不变；将来若重开，次数/单次资金/累计持仓/最坏剩余风险须先注册 | 浮亏加仓、挂单补单均通过同一风险门；max_open_trades与PairLocks不代替它 |
| 流动性/订单 | 使用上一节价差/参与率/深度限制；入场60s不成交撤剩余；退出使用经验证的原生market/reduce-only语义（若支持） | 无盘口/unsupported时不声称通过执行验收；网络不可用继续持久待退出状态，恢复后对账再尝试 |

状态机至少有 `RUNNING / ENTRY_BLOCKED / DE_RISK / EXIT_PENDING / HALTED`，原因可叠加，最严动作优先。状态、初始资金、峰值、日初权益、最近事件游标、待撤/待退出ID和重试次数原子持久化；启动先读锁和对账，再允许开仓。状态损坏/未知按禁开仓处理。安全动作幂等；禁止“重启自动恢复”或一条正常心跳清除hard latch。实现为本工程可审计风险模块，未来仅通过Freqtrade原生回调/RPC/订单路径，不另建交易引擎。

证据分级：A=源码/单元/故障注入；B=历史事件重放；C=独立dry-run和断线恢复演练；D=交易所沙盒支持的订单行为；E=另行授权的真实小额订单。A/B不证明真实止损成交或强平；C不证明交易所托管stop生效；D也不保证实盘流动性。研究阶段至少验证500边界、浮亏未平仓、部分成交/撤单竞态、DCA绕行、日界/资金费重算、进程崩溃/重启、网络恢复、重复退出和无余额。新风控版所有经济实验必须重跑；本轮不修改原盘来补缺口。
