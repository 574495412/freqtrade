## 原生账户扩展的实际进展

新增本地 `freqtrade/equity_wallets.py`，显式继承 Freqtrade 的 `Wallets`。固定上游版本为 `c051e9065c5b677f03817dd1f83cb980af1ed684`；运行核验来源清单中的 595 个文件。对应[上游回测文档](https://github.com/freqtrade/freqtrade/blob/c051e9065c5b677f03817dd1f83cb980af1ed684/docs/backtesting.md)已按原始字节下载，重点核对成交、费用和回测假设。这一股票组件是本地扩展，不是上游已支持股票的证明。

原生现货钱包在卖出后立即计入现金。扩展从实际原生 `Trade/Order` 的已成交数量、价格和费用读取待结算卖出净额，将其列为不可再投资现金；总现金仍保留该应收金额，不能因等待结算而把它抹掉。对剩余持仓另保留买入费用准备金；可买入名义金额包括明确的比例买入费用预算。现金同时与全部原生成交的净收支核对，不一致便拒绝继续，不以独立计算的账户收益替换原生结果。

交易日和现金结算日必须分别显式提供，不能把 XNYS/XHKG 的交易日列表直接冒充结算日。日历有有效期、币种、来源合同哈希和现金释放时点；成交需落在声明的交易时段内，拒绝午休、非交易日、日历尾部不足、未知及未来成交状态。重复刷新不重复记账。当前组件只接受单一 USD 或 HKD、无杠杆多头、固定比例报价币费用及已完成的原生成交边界；未成交挂单、其他币种初始持仓、分层收费和额外公司行动现金流仍不支持。

目标历史窗口内的标准周期依据是：[SEC 的 T+1 风险提示](https://www.sec.gov/files/risk-alert-tplus1-032724.pdf)说明美股多数经纪商交易自 2024-05-28 改为 T+1；[HKEX 清算说明](https://www.hkex.com.hk/Services/Clearing/Securities/Overview/Clearing-Services?sc_lang=en)说明香港交易所交易为 T+2。结算周期不能证明某个经纪商的实际入账时刻，也不意味着所有经纪商都禁止用未结算资金买入。本组件采用“只用已结算现金”的明确保守政策，尚未接入完整历史结算日历及异常清算事件认证。合成测试中的释放时点是测试合同，不是实际经纪商记录。

本轮 33 项新检查通过，连同原有历史、DataProvider、账户入口 30 项及新近程度 3 项回归，共 **66 项**。检查包括原生部分/全部退出、DCA、带非整数平均成本的现金对账、T+1/T+2、独立结算假日、午休/半日、资金不足、费用、重复刷新、错误输入及拒绝服务模式。生产模块完整 Ruff 检查通过；研究脚本仅对断言、引导后导入和字典写法应用明确的 lint 例外。

`native_synthetic_trace.json` 另保留 **4 笔原生合成成交、8 个时点**的现金及持仓数量核对。测试直接调用实际 `Backtesting._try_close_open_order/_process_exit_order`、`LocalTrade/Order` 和钱包方法；使用未联网的测试壳、数据库提交及非本测试目标的回调替身。没有启动完整 `Configuration → StrategyResolver/IStrategy → Backtesting.start → 历史账户结果` 链。因此这些测试是组件正确性证据，不是历史资金账户，也不是回测收益。

`EquityBacktesting` 的完整账户入口仍在原生初始化前拒绝。普通钱包、固定上游源码和普通加密路径未修改。要生成股票收益，仍需把本组件接入完整执行循环，并补整股/整手/价位、买卖侧费用税、股息权利与付款、公司行动、退市及必要时的借券。历史股票账户、连续 NAV、完整资金窗口结果和 bench 计数均为 0。

## 不同机制来源的筛查

本轮核对 [OpenSourceAP/CrossSection](https://github.com/OpenSourceAP/CrossSection/tree/9f053398c4995651d822e90d81526d0644c6f3e5)，固定提交 `9f053398c4995651d822e90d81526d0644c6f3e5`，保存原始代码及 GPL-2.0 许可证和字节哈希。没有把第三方代码说成 Freqtrade 或原论文作者的官方策略实现。

**研发转化能力 RDAbility**：源 Python 与旧 Stata 代码将年销售对数增长分别回归到 1～5 年滞后的 `log(1 + 研发支出/销售额)`，每个回归有截距、8 年窗口及至少 6 对有效观测，并有正研发频率筛选；取可用斜率均值，只保留当期研发强度最高三分位。并非所有五个斜率都必须同时存在。它考察过去研发投入转化为销售的能力，不能将普通研发强度改名当作它。原论文 [Misvaluing Innovation](https://dash.harvard.edu/entities/publication/73120378-ad1e-6bd4-e053-0100007fdf3b)本轮只读到作者、版本及摘要，未将摘要中的绩效当作本地收益。

源 Python 的 `shift(n)` 和滚动窗口按行计算，旧 Stata 按财政年设置滞后和窗口；存在财政年缺口时不能未经核对地宣称二者一致。下一阶段需要在原生输入所有者中实现逐财政年研发/销售字段、披露可知时点、缺口和未来前缀检查，再进入 Registry、实际 factor_analysis 和去重，而非用现有价格替代财务字段。

原始 **503 个美股、11 个港股**全部保留，沿用目标窗口 **2025-01-01～2026-08-31**，没有按收益删除证券或延长窗口。`rdability_input_admission.json` 实际核对结果：

|原始输入|数量|本轮状态|
|---|---:|---|
|能绑定现有年度披露骨架的美股|495|没有已接入的研发/销售长期财政年面板或源 Compustat 面板|
|缺少精确现有发行人绑定的美股|8|保留未知，不映射到相似证券|
|港股|11|没有准入的可比财务/披露面板|

在上述 495 个美股输入中，窗口开始前的现有年度骨架仅覆盖 492 个输入各 3 个、3 个输入各 2 个独立财政期末；修订申报数量不能当成独立财政年数量。这不足以直接支持最短的 6 对年回归。**没有扫描全部原始 companyfacts，不能据此声称更早财务数据不存在。** 本轮拒绝的是现有输入合同，未检验该经济假设，也未计算因子分数、调用 factor_analysis、添加 Registry 定义或运行资金账户。

另外两个来源避免重复计数：[OPLeverage](https://github.com/OpenSourceAP/CrossSection/blob/9f053398c4995651d822e90d81526d0644c6f3e5/Signals/pyCode/Predictors/OPLeverage.py)已在本地旧研究中失败，不作为新增因子；[LaborforceEfficiency](https://github.com/OpenSourceAP/CrossSection/blob/9f053398c4995651d822e90d81526d0644c6f3e5/Signals/pyCode/Placebos/LaborforceEfficiency.py)被源库明确列为 placebo，不因文件可运行就计作通过验证的 alpha。

## 证据、失败与后续边界

`source_intake.json`、`github_sources.json` 和 `official_source_receipts.json` 区分确实读取的内容、检索片段与失败请求。DTCC 公告的直接获取失败，未将检索到的结算异常线索当作已经认证的历史日历或零影响。原始论文、源代码、本地适配和资金绩效保持独立。

`tests_initial.log` 至 `tests_v7.log` 保留技术失败和修正：早期测试壳遗漏数据库提交隔离、回滚检查与合法时钟推进顺序不一致；另一个负向测试曾假设 DCA 的显示价格舍入会破坏现金对账，实际原生计算没有该问题，最终改为正向验证精确现金。没有因这些失败改信号、股票池、费用、持仓或评估窗口。一次宽范围格式化触及两份只读源代码副本，已恢复并核对为固定提交原始字节；源代码未执行，恢复记录独立保留。

收益比较的下一条件仍是每市场完整且同币种、同初始资金、同起止时刻、同现金及公司行动政策、同费用与终点估值的真实原生账户。美元与港币账户未定义资金和汇率合同前不合并。没有合格候选和完整资金账户时，不生成伪组合排名；未找到更高收益，也没有独立样本外、模拟观察或实盘验证。
