## 已补实的验证证据

沿用现有本地原生股票组件：Configuration→StrategyResolver/IStrategy→继承的Backtesting.start→实际Trade/Order/Wallet→实际ZIP及未平仓状态侧文件。没有新增独立资金引擎、改撮合、手工注入成交或修改生产模块。普通EquityBacktesting历史入口继续拒绝未准入账户。这不是上游Freqtrade官方股票支持。

两市场各6种固定夹具：无股息、付款未知、Jan6收盘到账、Jan9收盘延迟到账，以及相同未来事件每股1/999的反事实。每次均为独立进程、离线、1000初始现金、固定7个合成交易日、固定名义报价、整数股及费用、期末实际保留6股，没有虚构期末卖出。协议和24条实现路径先冻结后启动。

完整生命周期验证了：

- 实际除息前6股在除息日开盘卖出后仍有权利：每股10、夹具预扣10%，产生54净应收。上述税率仅为任意合成边界，不代表港美股真实账户税率。
- 另一个除息日恰在原生开盘买入6股，未获得该次股息，未用当日买入冒充除息前持股。
- 付款未知一直保持54应收，不能增加可用现金；付款及知识时钟均到达后只转入现金一次，NAV不重复增加。迟到付款前的全部账户边界与未知付款场景一致。
- 更改未来股息1→999、或截去该未来事件，除息前全部实际财务边界一致；Jan6到账前与未知付款场景一致。只认证本合成范围，不声称完整历史因果证明。
- 无事件的订单、开收盘现金/NAV、回调及净结果分别与前轮两市场持股夹具完全相同。

独立审核不导入候选策略或资金组件：从实际订单、原始夹具报价和费用/结算/股息合同，以Decimal逐边界重建费用、现金分区、实际持股、应收、到账及NAV。费用算术复用已保留且独立的审核函数，哈希绑定；不会把审核曲线当作主要账户结果。

每份ZIP只有已关闭的1笔交易、2笔成交，已逐笔与实际订单绑定；另1笔买入及期末未平仓Trade/Order在`native_trace.json`和持股净结果保留。原生ZIP利润0是未含股票overlay的诊断，不能当净收益。固定无事件期末1001.80、有54股息的期末1055.80只是合成算术；未来999场景更是故意极端反事实，所有CAGR、Sharpe和策略业绩字段均为null。

这些是继承的合成时钟和报价，不是认证交易所日历、历史价格或经纪实际到账。没有测试因股息到账而增加下一笔数量；本夹具固定600名义仓位，只认证现金转移及完整生命周期，既有单元边界的再投资证明保持分列。也未覆盖FX股息、特殊大额派发、due bill、ADR费用、股票分派、借券或其他公司行动。
