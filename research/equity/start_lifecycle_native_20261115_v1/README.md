## 所有权与接线

遵循当前 Vibe-Trading 的 factor-research / strategy-dev-manager：输入和因果性准入后，因子走 Registry 与实际 factor_analysis，策略走支持的 SignalEngine／原生执行／结果与 bench 读回。此次没有新增准入因子或注册结果；已有文档、实现与前轮封存逐项绑定。Freqtrade 原始 `c051e9065c5b677f03817dd1f83cb980af1ed684` 的 595 个文件重新核验。

新增 `freqtrade/optimize/equity_fixture_lifecycle.py` 是**本地合成研究扩展**。普通 `EquityBacktesting` 历史资金入口继续在原生构造前拒绝。新 mixin 仅允许显式 synthetic 配置和 ABC/USD 或 ABC/HKD，单策略、无缓存、固定清单、实际磁盘加载，不能用开关把 AAPL 等真实证券放进来。

实际链为 Configuration → ExchangeResolver／StrategyResolver → 原生 Backtesting 构造 → 本地股票 provider 调用原生 Feather 历史加载 → **继承调用的 `Backtesting.start()` / `backtest_one_strategy()`** → 既有日线交易日及开盘模型 → 原生 `backtest`、生成器、Trade/Order 和钱包 → 原生统计与 ZIP 导出 → 本地费用／股息净值快照封套。撮合、入场、订单和交易类没有另建资金引擎。

原生裁剪后的日线标签必须准确等于冻结首末交易日，再映射到实际开盘。每个完整原生事件阶段前记开盘持仓净值、阶段后按真实收盘估值；保留期末持股和待收款，不虚构强制成交。完整开／收盘网格缺失不能标为完成。

没有调用原生按整月报价推断小数精度的辅助函数：它会读未来日线并给输入附加列。合成交易所使用已声明固定 tick，成交另经既有执行规格检查。真实历史价位仍需来源合同，这不是用固定 tick 认证全窗口股票规格。

**原生 ZIP 的 Trade 绩效没有纳入本地费用／股息 overlay，不能当成股票净收益。** 单独的 `equity_fixture_result.json` 使用实际净值快照，保存现金、已付费用、未收股息、待结算卖款及期末持股，明确 `financial_strategy_performance=null`、历史账户 0、bench 0。原生 ZIP 的时间标签与交易统计只是诊断，不作为可比较净账户或官方股票支持。
