## 解决的一处原生执行缺口

新增本地扩展 `freqtrade/data/equity_execution.py` 与 `freqtrade/optimize/equity_execution.py`。固定上游提交为 `c051e9065c5b677f03817dd1f83cb980af1ed684`，重新核对清单中的 **595 个原始文件**；未修改这些文件。上述扩展不是上游已经支持股票的证明。

`EquityExecutionContract` 要求显式提供证券、币种、每手数量、历史有效区间、价位表和来源哈希。版本重叠、交易日覆盖缺口、未知证券及货币不一致会被拒绝。数量经实际上游 `amount_to_precision(..., TICK_SIZE)` 向下截到整股/整手；不足一手返回零，不向上凑单。价格经实际上游 `price_to_precision` 与精确十进制网格核对；越格成交直接拒绝，不将行情改价当成交。

`EquityFillValidationMixin` 挂在实际 `Backtesting._try_close_open_order` 的成交前边界，并沿用原生 `Order.close_bt_order`、`LocalTrade`、退出处理和已实现的结算钱包。它在修改成交对象之前检查：研究回测模式、现金钱包合同及时钟、交易时段/午休、证券版本、数量、价格、订单字段、未来订单、超卖和含买入费的已结算现金预算。未触及价格范围的限价单仍沿用原生未成交行为。

这不是完整历史执行循环。合成测试显式绕过构造函数建立测试壳，隔离数据库提交、清算更新及无关策略回调；普通股票资金入口 `EquityBacktesting` 仍在初始化原生账户前拒绝。尚未提供拍卖撮合、逐笔流动性、完整费用税、股息权利与付款、其他公司行动、退市及必要借券。不能把该组件或以下测试称为完整官方股票回测。
