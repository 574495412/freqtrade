# 港美股 Freqtrade 研究：年度高点新近程度与股票数据路径

**尚未找到更高可比收益的新组合。新增已接受独立因子 0，完整股票资金账户 0，净收益未知。** 本轮只研究港美股；本聊天此前的加密实验与账户不计入股票证据。没有订单、部署、服务修改、提交或推送。

## 结果与使用边界

冻结的账户目标日历窗口为 **2025-01-01～2026-08-31**，预热从 2024-01-01 起。沿用上一轮原始 **503 个美股、11 个港股**输入，保留失败名字和原始文件 SHA，没有按本轮收益删选证券。该已有输入队列不是无生存偏差的完整市场主表。

实际 Freqtrade 历史加载及策略数据路径接受 **475 个美股、11 个港股**，拒绝 28 个美股输入；原始 514 个名字仍全部出现在准入记录及诊断列轴中。比只检查账户目标窗口的上一轮多拒绝 GEV：更长的预热窗口包含非有限 OHLCV。不能将该拒绝解释为股票在整个目标窗口不可交易，也不能声称原始完整池通过。

本地“年度高点新近程度”假设的方向固定为：距离最近年度最高收盘价的日历天数越少，分数越高。没有看到结果后翻转信号或改变时间窗。

## 原生链实际完成了什么

引擎固定为 Freqtrade `c051e9065c5b677f03817dd1f83cb980af1ed684`，逐一核对固定源清单的 **595 个文件**。实际 Python 进程先加载 `/Users/chrise/GitHub/CZ-Agent/vendor/freqtrade`，再显式装入本地扩展；没有修改该固定原生树。

本地 `freqtrade/data/equity_provider.py` 继承原生 DataProvider，通过既有本地股票历史扩展调用原生 FeatherDataHandler 与 `load_pair_history(fill_up_missing=False)`。原始股票数据在原生去重/补齐前接受完整日历、唯一顺序、正价和有效成交量校验。

实际 StrategyResolver 加载 `RecencySignal`，实际 `IStrategy.advise_indicators` 生成分数。日线日期仍是交易日标签：向量化历史用于指标计算；回调获取原始及已分析日线时，必须提供有时区的观察时刻，且仅能读取软件日历中已经收盘的交易日。午休、半日、周末和节假日不会被当成已完成日线。收盘即视为可见是本地模型假设，不是逐条历史行情发布时间认证。软件日历来自 `exchange_calendars 4.13.2`，不是交易所逐日独立认证。

新增 `freqtrade/optimize/equity_backtesting.py` 是显式本地股票回测入口边界：完整账户合同未实现时，在原生构造、交易所、钱包及订单初始化之前直接拒绝。普通 crypto 的 Backtesting/DataProvider 路径没有修改。该入口不是已支持股票资金回测的宣称。

策略本身不发出交易信号，拒绝资金循环。股票成交时刻、整股/整手/价位、可用与未结算现金、卖出侧费用/税、股息权利/付款、证券生命周期/公司行动，以及做空借券和召回，仍未进入完整 Freqtrade 股票账户。这些缺口不能用另一个账户模拟器或注册一条结果来替代。

本轮核对 **202,574 个实际分数、1,335,862 个未来扰动/截断前缀值、8,748 项回调时点检查**。相关 33 项测试通过；核心扩展和测试 Ruff 通过。首次测试的 3 项时间戳单位/测试夹具失败及后续测试收集缺少无关 `optuna` 的记录均保留。未安装无关依赖；账户入口测试移动到不依赖 Hyperopt conftest 的测试位置后重跑通过。

时区校验增强前的源码及记录在 `frozen_v1`。首次重验证包装遗漏 `bootstrap.py` 符号链接，在计算新分数之前失败，日志及目录保留；修复包装后另行复跑实际 native 路径，见 `technical_revalidation.json`：全部准入记录和分数精确相等，沿用原 24 次诊断，不增加调用计数。

## Registry 与预测诊断

采用 Vibe-Trading 的 Registry 和 `FactorAnalysisTool` 原生实现，独立 zoo_root 只暴露实际 Freqtrade 策略分数，未修改全局 Registry。这个跨项目研究接入是本地扩展，不是 Freqtrade 上游自带因子研究库。

既有 `academic_high52w` 定义实际由拥有它的 Registry 计算，不能重复算新增因子。两个报价对照也明确不是原有含股息、拆股合同的核心动量结果。每市场四个分数、全段和两个年度入场切片，共 **24 次实际 factor_analysis**；298 个 IC 行及 894 个分组 NAV 单元独立核对，最大分组误差约 4.44×10⁻¹⁶。全段和年度切片存在重叠，不能当成独立样本数。

标签从前一月最后交易日收盘后的分数，预测本月首个交易日开盘到下月首个交易日开盘的**报价收益**；每市场共有 19 个不重叠月度标签。2026 年 8 月入场标签因下月开盘超出窗口而保留为不完整，不加入诊断。对照的一些早期标签缺 252 个交易日预热而保持未知，未补值，因此它们可能少于 19 个有效 IC。

分组 NAV 是费用前报价标签诊断，既不是资金账户，也没有实际现金、股息、税或组合再平衡。月份标签不覆盖整个目标资金窗口，因此不能把它们的末值或年化数字当成目标完整账户收益。

该候选停在因子/输入诊断阶段；没有进入 hypothesis/configuration/SignalEngine/资金 backtest/bench，也没有把其他项目 bench 注册为 Freqtrade 账户。停止的原因既包括这一本地定义的数值门槛失败，也包括输入与样本合同不足；不能据此否定原始文献的全部经济结论。

## 多来源学习及原始方法的差异

[Ma、Whidbee、Zhang 的原始论文](https://www.aobf.org/wp-content/uploads/2020/06/3.pdf)第 5 页明确使用拆股和股息调整后的最高收盘价，定义“1 − 距年度高点的日历天数 / 364”；论文组合还涉及盈余事件与三个月重叠持仓。本地固定为 `(t−364 天,t]`、最近一次精确并列高点，以现有供应商报价做月度诊断。没有认证源数据调整单位，也没有接入 Compustat/I/B/E/S 事件，因此不是原文 PEAD、股票池或账户收益复现。

[George–Hwang 原文](https://www.bauer.uh.edu/tgeorge/papers/gh4-paper.pdf)及现有 Registry 证明“高点接近度”已经研究过；不能将新近程度与接近度混淆。[QuantConnect GitHub issue #120](https://github.com/QuantConnect/Tutorials/issues/120)只是高点数据需求的开放议题，不是一份已实现的可运行策略。两份论文及 issue 的实际下载 bytes/SHA 保存在 `inputs.json`。

上一轮 [QuantConnect GitHub 配对模型](https://github.com/QuantConnect/Lean/blob/78de2ccd1e8d1544bd69f1b0494493f56559ec12/Algorithm.Framework/Alphas/PearsonCorrelationPairsTradingAlphaModel.py)、[YouTube 教程](https://www.youtube.com/watch?v=uhuwErm1no8)、[X 配对线索](https://x.com/MatiasScalbi/status/2063042609816252666)、[抖音指数权重线索](https://www.douyin.com/video/7673858811899284751)的逐项证据状态沿用并绑定旧 intake SHA。没有新观看视频或认证社交账户收益；双腿借券、分钟历史和历史权重可得性缺口不因本轮完成而消失。

另查 [FINRA 对卖空未平仓与日度卖空成交量的说明](https://syndication.finra.org/content/short-interest-what-it-what-it-not)：二者不是同一数据，不能把现有 FINRA 日度成交量因子改名为未平仓拥挤度，算作新的机制。此线索尚未准入，也没有因子/账户运行计数。
