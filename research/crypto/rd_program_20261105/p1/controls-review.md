## 核算与时间边界

- 8个B0现金控制均保持1000 USDT、零订单、零资金费和零风险敞口；USDT计价不等于已经模拟美元脱锚风险，现金Sharpe／Sortino／Calmar的零分母保持null。
- 8个B1均从1000 USDT开始，00:05记入买入事件，快照采用事件前状态，所以00:05仍为1000，00:10才包含持仓。期末仍有一笔未平仓，`natural_complete_campaigns=0`；预计退出费用是净值储备，不把假想退出算成已成交或完整campaign。
- 买入成本和预计退出成本分别计一次；冻结执行成本代理已折入手续费，未再加一次滑点扣款。合约保证金本金没有被当作亏损重复扣除。
- 合约长窗每种成本包含1823个BTC资金费事件、短窗38个，时间／费率与源文件完全匹配。多头正资金费率对应负现金流，负费率对应收入。事件在同刻快照之后计入，下一5分钟快照才看到，符合已登记的pre-event口径。
- 这里的资金费是**实际历史费率×历史小时mark OPEN的模型现金流**，不是经过认证的交易所客户实扣账单。历史预处理允许不超过1秒的时刻向下归整；对于本控制00:05入场、23:55末点及BTC的8小时间隔，不改变5分钟快照中事件的归属。它不是可以提前知道的因子输入。
- “99%”是含入场成本的**最大预算990 USDT**，不是已实现99%仓位。合约长窗受0.001 BTC步长影响，基准／压力实际占用约937.23／937.89 USDT；短窗约975.80／976.48。现货约989.16–989.65。现行归档步长与最小名义额校验通过，但历史规则是否逐时点正确仍未证明。
- 压力成本下，所有B1成对终值都降低。现货数量会因含成本预算和步长取整下降一档，因此其回撤可以略低；这不是风控改进或纯粹固定数量下手续费的导数。

## 补充评分表的指标口径

| 指标 | 定义／限制 |
|---|---|
| 净收益、5m参考MDD | 全部已有快照，至`end_exclusive−5分钟`；现货为OPEN参考，合约为trade OPEN条件性参考，不冒充可成交bid或5m mark |
| 回撤持续期 | 从最近一次达到历史高点的观测时刻到恢复；期末未恢复则截尾并单列标识。另给最大回撤的峰、谷、恢复时刻及峰谷耗时 |
| 最差完整日 | 相邻UTC00快照的收益；长窗607个完整日，短窗12个。最后UTC00到23:55不足一天，不参与日比率 |
| 最差完整周 | Monday00 UTC到下一Monday00，两个端点必须存在；长窗86周，短窗仅1周，边界零碎周不拼接 |
| 年化与Calmar | 只在上述完整日首末端点之间计算几何365日年化；Calmar分母为**相同时间区间内的5m参考MDD**。零回撤记null，不把最终不完整日收益混入分子 |
| Sharpe／Sortino／ES95 | 复核已有完整UTC日序列；365日、Sharpe样本标准差ddof1、无风险率0；ES为不高于经验5%分位数的日收益均值，并记录实际尾部天数 |
| 成本 | 分拆模型入场佣金／执行代理与期末假想退出储备；资金费净现金流独立列示，不称真实费用 |
| gross／net／时间暴露 | 这些控制只有现金或BTC多头，所以net=gross；给观测快照均值／最大值、期末名义额、按已知买入事件到估值终点的持有时长及时间占比。快照均值不冒充连续盘中暴露 |
| 换手 | 已模拟成交的单边买入名义额÷初始1000；期末假想卖出单列，不混入已成交换手 |
| 集中度 | BTC持仓时单币敞口100%；只有BTC净贡献为正时，其正贡献集中度才为100%。当前亏损B1没有正净单币贡献分母，该项为null；不把它写成0%分散化 |
| 容量 | `unknown`：没有历史盘口、排队、冲击或真实成交容量证据 |
| 端点 | 同时列旧23:00参考净值、新23:55参考净值、差额，以及合约独立小时mark端点／回撤，避免混用旧锚点与新末点 |

短窗只有12个完整日和1个完整周，年化比率与尾部统计非常不稳定，只作描述，不是未来收益预测。长窗也已被观察和使用，不能称独立OOS。合约即使始终1x，资金费和成本降低权益后，名义敞口／剩余权益的比值仍可能略高于1；这不表示本控制中途提高了杠杆。

原 `audit_controls.py` 的终值恒等式使用已输出的资金费事件，因此它本身不证明没有漏事件；本次派生审计进一步逐一对照原始费率和mark来源，补齐了这16个既有结果的事件成员检查。复用原冻结runner时，空资金费Series及非结算小时mark完整性还需由外部数据验收负责；本次数据经只读检查完整且有限，不为此重写旧源码或重跑账户。

## 原生观察器边界问题与修复

独立审阅发现新增P1 native observer可在窗口结束事件处理后，错误地用窗外已平仓现金填充窗内未观测的非空仓缺口。最小合成反例：00:05开仓，00:30=end才平仓亏100，旧实现把00:10–00:25填为900且没有缺口标识。

该问题已在这份新原生观察器**首次金融运行之前**修复：第一次`current>=end`时在向原生调用方yield之前冻结观察窗口；后续yield原样透传，不再更新窗口状态；完成操作幂等。独立运行7项原生配置／观察器合成测试通过，覆盖end和晚于end的退出、以及窗内flat而end时现金改变的情况。证据见 `native/verification.json` 的 `pre_financial_revision` 和作者`financial_backtests_run_by_author=0`。

本次修复不影响这里已完成的16个B0/B1控制结果，它们使用独立的固定账本控制实现；也没有修改、停止、重启或激活现有paper服务。所有控制和补充评分表仍为工程／事后参考，`orders_enabled=false`、`production_eligible=false`、`RD1_applied=false`。
