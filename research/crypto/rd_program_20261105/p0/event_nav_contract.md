# 同刻事件与账户净值证据合同

状态：规格已明确，完整历史证据仍不足。本文不替换原版引擎的事件顺序，不将某种假设排序包装为已验证事实，也不启动新的金融试验。

## 时间与事件

每条原始事件至少保存：账户／市场／交易对、源事件 ID、交易所事件时间、发布或发生时间、首次本地接收时间、订单创建／提交／确认时间、成交时间、序列号（来源提供时）、原始消息 hash。重复 ID 必须幂等；相同 ID 内容冲突、时间倒退、无法对齐的时钟均阻断事件验收。缺失不可补为 0 或用行情 bar 开盘时刻替代。

同一时刻的 funding、fill、cancel、持仓与余额更新，优先使用实际来源序列和因果关系。若无法建立唯一顺序，应保留多个可行状态及其影响，不能默认“funding 先于成交”或反之。只有影响能被完整证据限定且不改变验收结论时才讨论晋级；当前 minified export 缺少订单创建时间及逐单 funding allocation，尚不满足此条件。已保存的六个告警 callback trace 是局部观测，不是所有历史账户的完整事件账本。

## 状态与估值

- 现货：所有账户现金（含订单占用）加真实持仓按同期可卖出价估值，减尚未计入的退出费用／执行成本；不能再减一次已含于总现金的 reserved cash。
- 合约：抵押本金加已实现净损益、已结算资金费和当前未实现损益，减未入账费用与退出成本；保证金转移或冻结不直接作为损失。价格、持仓、余额与 funding 累计口径必须统一，避免重复记账。
- 同步 5m 观测保存事件前／后的明确口径、行情类型及其时间／接收证据。缺失价格不能用持仓消失、零浮亏、最后现金或未认证的 trade OPEN 静默替代。
- 初始权益、历史高水位、日基线、部分成交、未完成 campaign 和全部待成交订单均保留；非自然终止的 `force_exit` 单列。以账户净值而非平仓利润或止盈次数计算收益与回撤。

## 当前实际可用范围

P1 新观察器提供原生生成器逐时间事件前的 5m trade/spot OPEN 参考；仅在能证明全程无 trade 对象且现金不变的间隙补点。小时 mark 独立保存。它有现金恒等式和完整性审计，但不是交易所真实结算对账或盘中最差可执行价格。

合约输入目前只有小时 mark，没有经验证的 5m mark；历史 funding 的最终费率用于成本模型，未证明其发布／接收时刻。盘口深度、排队、冲击、逐时历史规则及可成交容量仍未知。现货 OHLCV 也不是可成交 bid/ask。上述缺口保持候选经济准入为 false，不能通过扩大诊断次数、调指标检查点或提高杠杆来绕开。

## 闭合所需证据

后续独立登记的数据包需要包含同期 bid/ask/depth、历史 mark/index、funding 发布接收与结算事件、订单创建／确认／成交／撤单、持仓和余额序列、规则版本，以及可复查的原始消息收据。在这些数据存在之后，才能实现完整事件重建、RD1 原子入场风险预留和订单行为验证。本任务没有改动现有 paper 或真实账户来采集这些证据。
