# P0 RD1 离线风险模块

这是冻结计划 `P0_RISK_MODULE` 的标准库实现和**合成单元／故障证据（A层）**。它没有交易所、网络、Freqtrade RPC、订单执行、行情抓取或通知代码，也未接入正在运行的现货／合约模拟盘。它不是新的交易执行引擎，不能据此宣称500 USDT熔断已在运行盘生效。

从 Freqtrade 工程根目录运行：

```sh
python3 research/crypto/rd_program_20261105/p0/risk/test_rd1.py
python3 research/crypto/rd_program_20261105/p0/risk/run_validation.py
```

第一个命令只跑临时目录中的测试。第二个重复执行同一套测试，并在本目录生成 `summary.json`，记录实际测试结果、代码hash、冻结计划hash与证据边界；不运行收益回测，不占用官方6次recursive＋2次lookahead诊断预算。代码使用Python标准库；持久层使用macOS/Linux的`fcntl`单写者文件锁。

## 输入及权益合同

`Snapshot` 必须是一个已对账的**完整账户快照**，不是累加成交事件。`cursor` 单调递增；同cursor只能重复完全相同的内容。`Decimal`禁止NaN/Infinity和二进制float。所有时间必须带时区；所有金额、头寸和订单身份必须由将来的适配器证明来源。

- 现货 `balance` 明确是**含挂单冻结资金的总现金**，已支付成本已经在现金中；权益为现金＋持仓数量×同步spot bid－尚未支付的退出成本。挂单余量计入未来敞口，不再从权益扣一次。
- 合约 `balance` 明确是不含未实现损益、包含占用保证金、已实现损益及已结算费用／资金费的wallet balance；权益再加带符号数量×(mark－开仓价)，减未结算应计资金费和退出成本。`collateral`仅用于可用下单余额约束，绝不再加减权益。应计费用正数为支付、负数为收入；同event ID重复会拒绝，已结算事件不会二扣。
- 输入缺失／错误价格类型／不完整资金费／对账差大于0.01均禁止新增风险；不会把未知填0或沿用上次良好权益继续批准。
- `day_start_at`必须是对应UTC日的准确午夜，且同日基准不可改写；不把午间首个样本当日初权益。如何取得午夜权益须由数据模块提供真实证据。
- 报价、账户及订单状态超过15秒或相互差超过15秒则不能新增风险；允许的交易所／本机未来时间容差为2秒。模块不自带5秒轮询器，持续调用／断线发现属于未来适配器验收。
- 相关性输入要求冻结36／40币池的完整成对矩阵，720小时窗口、一天内且非未来的计算时刻。按相关性`>=0.7`建立**连通簇**，未持有中间币也可连接两个持有币；矩阵不完整则全部按同簇处理。本模块不凭空生成收益或相关系数。

## 持久状态与动作

`RD1(directory, account_id, market, create=True)`只用于明确建立一个全新的**离线研究账户**。每账户独立目录、身份及成本情景；不可跨账户抵消损失。再次初始化、身份不匹配、状态缺失／损坏、冻结plan hash不匹配均抛出`StateError`，调用方必须保持禁开仓。`create=False`恢复状态，恢复后仍需当前快照对账，重启不会解除任何锁。

每次决策先持久化再返回：写前完整状态日志 → fsync → 原子replace主状态 → fsync目录 → 删除已提交日志。主状态及日志有SHA-256校验；持久化失败会毒化该实例，不能继续返回许可。崩溃后有效日志按序恢复；损坏不会自动“修成空账户”。这验证的是文件协议与注入故障，不保证硬件掉电、恶意重写、观测事件尚未写入前崩溃等所有情形。

| 条件 | 状态／动作意图 | 恢复 |
|---|---|---|
| 权益`<=500`或HWM回撤`>=15%` | 持久hard latch，撤风险增加订单，持久reduce-only全退出意图；未平仓为`EXIT_PENDING`，对账后无持仓无订单为`HALTED` | 明确重新授权＋事故审查＋新鲜对账、flat、无订单，且触发条件消失；不重置初始1000／HWM |
| UTC日损`>=2%` | 同上，但独立日锁 | 下一UTC日、flat、无订单、对账通过且无hard latch；日界不清hard latch |
| HWM回撤`>=10%` | 停新增，`DE_RISK`，gross目标30%并保持单币／簇／净敞口约束 | 触发消失后明确审查；不会自动抄底 |
| 陈旧数据／时钟／3次API错误／未知订单等 | `ENTRY_BLOCKED`，撤风险增加余单意图；技术锁持久化 | 连续5分钟新鲜且对账一致，间隔超过15秒重新计时；hard latch存在时不清技术锁 |
| 单币10%／总gross及abs net60%／簇30%／6笔超限 | `DE_RISK`及约束目标意图 | 只减风险；后续对账确认限额内 |

全量权益新鲜度与风险减少动作的可安全执行条件分开：仅报价陈旧／缺失，但订单、头寸、连接和对账可信时，允许领取`CANCEL_ENTRY`，也允许领取**已经被硬锁／日锁要求**的数量型`EXIT_POSITION`。它们不需要猜价格。未知订单、头寸陈旧、无连接仍不能领取。需要百分比权益目标的`REDUCE_EXPOSURE`在权益未知时不可领取。

`evaluate()`只返回持久意图，**不发送订单**。`claim_action(id, now)`也只是记录“准备交给未来原生适配器”的领取次数；它不执行。动作ID按账户和生命周期目标稳定，部分成交只更新剩余量。相同对账游标不得再次领取；不论先前结果成功还是未知，都要新拉订单／成交／头寸并推进游标后才能考虑重试。已记录的领取和hard latch均跨重启保存。保护退出不被撤销；入场60秒未成交只撤剩余量。`REDUCE_EXPOSURE`给出组合约束，具体减仓分配需要未来经验证的Freqtrade原生适配器；不能把它称为已完成减仓。

## 新增风险门

`assess_entry()`针对同一完整快照检查新trade与正向调整：DCA=0；已有同pair持仓或未结入场单不能叠加新entry；替换须先撤单并新对账。保守名义额按提议价格和同步价较大值计算。每笔预计风险包括固定5%价格距离和**冻结情景双边成本**，同时受0.5%权益、单币／总／簇、余额、杠杆1x、精度／最小名义额、20bps价差、前小时成交量0.1%、20bps内对手盘深度1%约束。不为凑最小订单增大仓位。

返回的`entry_allowed`／`assess_entry`不是可直接提交交易的授权token。未来适配器必须串行对账、原子预留待下单风险，再经同一门检查；不能并行使用同一快照发出多笔尚未入账的订单。本模块没有实现交易执行或这些原子预留，故**不可直接上线**。盘口／相关矩阵／对账bool只是显式输入，本模块不证明它们来自真实、及时、完整的数据。
