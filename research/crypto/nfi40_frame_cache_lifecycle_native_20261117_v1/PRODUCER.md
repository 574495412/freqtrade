# Native lifecycle producer preparation

This addendum supplies a future actual official `Backtesting.start` producer for the unchanged frozen short technical plan. It does not release or execute that producer. The earlier preparation files remain byte-identical; their status describes the earlier preparation stage.

`native_producer.py` reuses the original NFI500 runner's source/data checks, official configuration and offline exchange metadata, unchanged NFI source, original lossless raw/indicator/row storage, fill-cash audit and observer. Only the analyzed private cache changes between variants. The native getter, matcher, quantity rules, funding, strategy decisions and wallet are untouched. The short window retains native short-input precision inference; it does not repair the old full-history monthly-rule gap.

`capture_native.py` observes original calls once. It records source signals, native DP slices, callback inputs/returns, exact raw trade/order fields, order transitions, source decision state, hourly/final wallets, native trades, reset/clear and cleanup. Native JSON rounds some values, so raw fields are also encoded using `float.hex`. Full payloads go to JSONL; memory keeps semantic SHA256 summaries and actual coverage keys. Both summaries and the complete JSONL digest must agree. Only real wallclock refresh/performance metadata are excluded; simulation clocks and all custom-data values remain exact. Borrowed-frame mutation or unsupported types abort.

`execute_pair.py` is a future serial controller. A child cannot declare its own terminal success: the controller waits for the actual process exit, binds its receipt SHA, verifies native ZIP/full-trace hashes and then uses the sealed comparator. A failed or incomplete attempt stops the pair without retry. Missing actual entry/add/partial/full coverage is not admission; detached fixtures never satisfy that requirement.

The old success-only gate still requires both NFI500 and all four HS accounts to finish successfully, plus an exact root release and shared lock. If NFI500 really fails its resource guard, this produces a known circular dependency. The recovery branch is **not implemented**. A future separately frozen version would need actual controller/worker terminal-failure evidence, bound process identities and receipts, lock availability and explicit root release. This preparation never infers terminal state from timeout or lockfiles and never bypasses the old gate.

Only detached object/static tests are permitted now. Actual native lifecycle coverage, the separate synthetic native matching fixture producer, full-window account parity and replacement admission remain unknown or unimplemented. Nothing in this study changes the running NFI500 or HS implementation, starts orders, or asserts higher returns.
