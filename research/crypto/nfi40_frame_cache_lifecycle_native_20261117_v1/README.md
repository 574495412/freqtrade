# Native cache lifecycle verification preparation

This study is prepared and held. No `Backtesting.start`, new wallet, matching lifecycle, or financial account has run here. The actual replay producer is deliberately not implemented or admitted yet; a separate producer freeze and root release are mandatory. The running NFI500 controller and pending head/shoulders queue remain untouched.

The fixed real replay compares the existing Zstd LRU4 analyzed cache with the frozen 4,096-row/32-block prototype. Both sides use original NFI X8 source bytes, the original ordered 40-pair configuration, 5-minute native matching, 800 startup candles, 1x leverage, six slots, 1,000 USDT and 15bp per-side fee proxy. The fixed account window is 2025-03-01 through 2025-03-17 exclusive. This is a storage engineering experiment, not a new strategy candidate or a return comparison with the historical full-window account.

The window was selected from the already known original 15bp native archive using lifecycle fields only: the earliest campaign with multiple entries and exits, completed within 30 days, is XRP from 2025-03-03 19:55 to 2025-03-04 14:40 UTC. Its archived four fills cover initial entry, position addition, partial exit and final exit. The fixed first 16 days of that month surround those events and give approximately 5,408 analyzed rows including startup. Archive outcomes were not used to select the window. A new flat-start short account may behave differently because capital, prior positions and indicator history differ. Actual lifecycle coverage is therefore **UNKNOWN** until a complete native replay runs; missing coverage must fail admission, not trigger window or parameter searches.

`fixtures.json` defines supplemental mechanical native fixtures for deterministic entry/add/partial/full events, block boundaries, cache eviction, clear/reset and teardown. They require actual official wallet and matching paths when eventually implemented. Their synthetic strategy is separate from unchanged NFI and cannot certify NFI lifecycle coverage. Current `test_contracts.py` uses only synthetic JSON receipts to check the admission/comparison logic; it exercises no native matching.

The future producer must record actual native DataProvider reads, callback inputs/outputs and profit-target state, non-minified orders with creation/fill timestamps, entry/add/partial/full events, native exports, hourly wallet state, reset/clear and cleanup. Both variants must agree exactly after an explicitly limited wall-clock/path normalization. Simulation clocks, signal fields, callback values, fees, quantities, funding, NAV, order lifecycle and original source hashes must never be normalized away. Cache wall-clock lastrefresh values may differ between independent runs; their original-object preservation is checked within each run. Native `Backtesting.cleanup` only restores logging/database mode; cache clearing must be observed separately and cannot be inferred from cleanup alone.

`receipt_contract.py` refuses detached callbacks, slice-only probes, synthetic substitutes, missing event categories, missing NFI callbacks and any unequal receipt field. The actual producer and independent full-fill capture are still outstanding. Unit tests of this comparator cannot authenticate an arbitrary receipt or replace the future producer review.

`admission.py` requires the preparation freeze, a separately reviewed producer freeze, a root release bound to both hashes, and successful NFI500 plus head/shoulders queue completion with matching process/result hashes. Its context manager acquires the same NFI500 shared worker lock plus a local lock, nonblocking, and rechecks all prerequisites after acquisition. A future producer must hold those locks through native start, exports and cleanup. There is no automatic resume, retry, live-controller replacement, historical precision repair or financial promotion in this preparation.

The earlier small-frame negative benchmark and full-width alias benchmark remain sealed in the preceding study. They support this next engineering question but do not prove full native lifecycle parity, a 40-asset production speedup, corrected historical execution, or higher returns.
