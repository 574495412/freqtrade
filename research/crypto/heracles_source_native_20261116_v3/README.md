# Heracles通道策略：4个完整原生账户完成，单策略及固定组合失败

本轮新增4个完成的Freqtrade历史模型账户、424笔原生Trade记录、848笔模拟成交、58,368个小时净值点。Heracles全段净收益和风险门槛均失败，四个事前固定组合也全部亏损。没有找到更高可比收益，没有接受新的独立alpha，整体目标仍未完成。

固定BTC/ETH、现货、USDT、1倍、两槽位，实际初始1000或500；保守每边20bps、低费13bps，分别为10bps佣金加10/3bps执行预算的原生quote-fee代理。共同窗口为UTC2025-01-01 00:00至2026-08-31 23:00，共14592小时。2025和2026片段来自同一连续账户，不重置资金。未替换原广池永续、股票或其他队列，也不把本两币结果当全局赢家。

## 方法、版本与原生链

原始Heracles.py字节未修改：DCP为10根Donchian位置，KCW为20根原版Keltner宽度；原参数DCP滞后15、KCW滞后9，比值在[.16,.75]入场，exit_long恒0，使用源码ROI和stop−.256。源码IntParameter构造默认16与buy_params15不同，实际原生初始化读回的是15；并非看到结果后选择15。保留原生默认limit订单及当前引擎退出行为，没有超参搜索。

ta作者版本未固定。本地明确选PyPI ta0.11.0，捕获sdist SHA和8份原始Python模块，匹配tag的MIT原文保留；只在本研究目录加载，没有修改共享虚拟环境。阅读相关Keltner/Donchian/utils/包装函数，未声称审完全部库。它是声明的兼容环境，不是认证作者当年的依赖。

原始源码不能直接通过当前原生DataframeValidator：原生加载附带open_count/high_count/low_count/close_count/max_count等nullable精度辅助列，ta.dropna将有效行情一起删掉，BTC3749→1830、ETH3749→2846。显式本地IStrategy子类HeraclesNative只把原始六列OHLCV交给不变源码，随后恢复未动的原生辅助列；任何真实OHLCV行被源码删去仍拒绝，原生dataframe检查保持开启。该接口适配不是源文件字节修改，也不能叫未适配源码直接运行。

## 独立对账与成本路径

9项唯一接口/收据检查通过。真实原生构造及初始化核对14,940个有限指标值、7296个目标4h转换行；三个截断/未来扰动重算比较71,316个前缀单元。该技术预检在v2复核，v3明确复用，不加成新的独立观察数。源码价格、指标、参数、实际转换时钟与独立滚动算术一致；当前源数学及前缀范围不等于完整未来因果认证或新因子有效性。

独立审核不导入候选计算器，以实际ZIP订单重建现金、持仓和每小时含退出费准备的NAV，核对58,368小时。最大NAV差3.64e−12USDT；另审14,592个原生quote余额及26,332个基础币余额，最大quote差3.52e−12。只有实际持仓为0才允许原生省略零基础币余额。原生quote现金的剩余入场费在实现时确认，经济现金另保留该准备，未把原始钱包quote直接当费后净值。

1000保守实际持仓路径的毛价格损益+161.52、实付费用209.97、剩余退出费准备0.9415USDT，导致约−49.39USDT净变化。低费账户的价格损益+73.47、费用139.32、准备0.6038，净变化反而更差。四个账户两币的向量信号SHA完全相同，但两成本的原生交易路径有126个对称差条目；原生费用敏感ROI退出与后续现金路径不同。不能把保守费用加回去代替低费原生账户，也没有据此重调退出。

独立审核初版的重建曲线与原生曲线吻合；最终报告和组合明确改为直接读取原生观察曲线，初版分析源码/结果保留。此为报告来源校正，没有资金重跑。图的输入及SHA另在figure_sources.json。

## 失败记录、终端时钟及边界

v1保留模板覆盖源ROI/stop、原生辅助列触发dropna的预检失败，随后首个资金进程在只读信号收据要求可选做空列时失败，未进入撮合循环。v2只修该收据，首个进程完成历史循环后在终端观察器把dict-of-lists误当list时失败。两次失败均无完整ZIP/账户结果，保留全部目录、源冻结和日志，不计成功。

v3只修只读终端收据签名，之后四个资金进程均exit0，无进一步金融重跑。它们与前两版的源指标、参数、止损、ROI、订单规则、资金、币池、成本、窗口及组合权重均未变。46条金融实现/配置/来源路径在v3启动前冻结，未改变；v1的109及v2的83封存路径、旧NFI312和carry633路径复核不变。

原生handle_left_open在历史循环之后使用最后4h行的OPEN及20UTC标签生成force_exit，不是23UTC真实卖出，也不是最后close。最早terminal文字说明误写finalclose，v3基于实际owner代码更正并保留旧说明。实际最后yielded detail clock为次日00UTC边界，最后共同观察为23UTC。终端收据记录该阶段和实际未平仓Trade，审计将这4笔post-loop订单从所有共同小时账排除，即使其原始timestamp写成20UTC。没有修改原生终端撮合或借后置强平补高共同端点收益。

这是历史OHLC模型，固定快照价位/最小金额、费用与滑点预算、limit范围成交，不认证历史全部交易规则、排队、实际订单簿或私人佣金币种。小时DD不是5m或更短风险上界。窗口和旧控制事前已看过，无独立OOS、纸盘或实盘证据。每个资金进程独立、单工人，250ms RSS采样峰值约453MiB，非连续峰值认证；当前新协议512MiB磁盘护栏是资源设置，未改旧协议或清理既有证据。
