# 资金费一次归属：完成20个原生账户，仍无合格新组合

本轮把上轮固定成交路径的资金费诊断推进到**完整原生账户重放**，包含后续现金、数量阶梯和净值反馈。20个实际进程全部退出0：16个完整资金费情景账户＋4个原口径技术复跑；另4个原8bps账户复核复用，不算新增回测。

两个名义时序模型下，BTC500＋ETH500来源组合在8bps约+6.05%，但15bps约−51.61%，2026年连续切片约−44.91%。完整固定晋级仍失败，0个新增独立合格alpha或组合，没有部署、订单或运行服务变更。两种情景都保留，没有挑更有利的结算顺序，也没有降低费用门槛或改变来源方向、小时、币池、权重。

## 所属实现和明确合同

策略沿用上轮固定`CarryRules.py`，作者来源为[Wu/Pinsky GitHub](https://github.com/wzf01195010-png/Crypto-day-night-effects/tree/5693993e108f2b3668bd21b1dd36ae31f79d8fcd)，BTC08/20UTC反转前一天同类时段，ETH05反转、17做多。策略字节不变；原作者全样本选择、来源统计失败、Kraken现货与本地Binance永续差异均继续保留。

财务所有者为固定Freqtrade `c051e9065c5b677f03817dd1f83cb980af1ed684`的`Backtesting`、`LocalTrade`、`Order`及原生钱包。新的`FundingOwnershipBacktesting.py`是**本地原生模块扩展**，覆写资金费回调及整仓成交前的资金费转入步骤，其他撮合、信号、钱包、手续费、风险、精度和数量计算仍调用固定原生实现。它使用私有回调，不宣称上游已提供稳定的此项插件接口，也不是上游默认回测行为；原包文件没有修改，未建立另一套账户模拟器。

冻结三种口径：

- `inclusive`：完全调用原生回调，保持`open<=event<=close`。四个15bps全账户复跑必须逐笔与逐小时精确再现上轮。
- `before_orders`：名义事件T由T时点下单之前的持仓归属，生命周期为`open<T<=close`。
- `after_orders`：T时点成交之后的持仓归属，生命周期为`open<=T<close`；持续持有仓位仍正常计入当前事件，正在整仓关闭时在原生订单记录费用前确定最终金额。

不能只把累计函数的右边界改成排除：该函数也会用于尚未关闭仓位的当前应计。实现区分正在整仓退出与持续持有，沿用原生订单中的已分配资金费，只设置剩余累计金额；原生订单成交再分配后，重复回调不会重新叠加同一生命周期资金费。

活动合同只支持一笔完整入场和完整退出，无DCA、部分成交/退出或仓位调整。7个真实原生Trade/Order夹具检验整点关闭、新仓进入、持续持有跨两个正负费率事件、重复调用，以及关闭扩展后的原生委托。首次夹具暴露待成交订单filled=0不等于预期数量的错误，修正后又补齐夹具缺少的native`ft_price`。失败均保留，发生在金融登记之前；最终7项全部通过。

## 完整账户窗口

持续2025-01-01 00:00至2026-08-31 23:00 UTC，每账户14,592小时点；年度切片沿用同一账户和持仓，不重置本金。每币500USDT、最多1仓、0.99原生可投资现金、1×逐仓设置、5分钟撮合、原生灾难止损和强平。1×设置不代表每小时名义额/净值恒为1，继续保留上轮固定数量持仓的敞口漂移。

单边成本代理15/8bps用原生手续费表达，另计各情景资金费。两个实际500钱包逐小时相加为1000，无转账或再平衡，不缩放1000曲线。排名用处理当根事件前的小时mark净值，含浮盈亏和剩余退出费预留；原生终点强平余额另列。小时回撤不是盘中最差回撤或实盘可成交清算值。

## 一次归属和现金反馈的证据

20份实际原生ZIP和291,840个新增完整小时净值点均已核对，其中16个情景账户233,472点，4个技术账户58,368点。四个技术复跑的1238笔交易和全部小时NAV与原来完全相同。原口径仍可复现，没有覆盖原模型或把原记录改称修正结果。

16个活动情景账户逐笔用独立标量规则复算实际费率×原生小时mark×实际数量×方向，并核对原生导出资金费；每个名义事件最多归属于一个实际生命周期，没有旧版BTC的290个双生命周期事件。成交现金按Decimal复核；实际持仓/换向、现金、数量阶梯、指标和完整净值也通过既有独立核对。新原生回调实际执行次数、空的关闭上下文和政策模式记录在各账户侧文件，未仅靠配置宣称执行成功。

BTC来源15bps的先结算/后结算模型有0/1笔实际数量变化；8bps均有8笔。相对原含边界模型，BTC完整终点现金差额分别为：15bps +0.1343/+0.1857USDT；8bps +0.1221/+0.1775USDT。ETH来源的信号时点不在资金费边界，此次数量和净值保持一致。

实际路径中的最大小时NAV差额：BTC8bps先结算约3.13USDT、后结算约10.29USDT，明显大于仅看最终资金费现金的小差额。某些完整重放的终值差额甚至与上轮固定成交诊断方向不同。因此不能把固定成交资金费差加回旧NAV代替完整回测，也不能以原诊断差额小就证明未来数量反馈小。`cash_feedback.json`和`quantity_feedback_examples.json`给出实际交易数量变化及首批实例，未凭空重建假成交。

原生ZIP的配置导出没有保留任意`research_`元数据，未修改ZIP来补标签。政策绑定来自登记计划、适配器SHA、实际`funding_policy.json`、回调审计和逐笔独立资金费验证；复现需要本地扩展及计划，不能只拿ZIP当作上游默认行为。
