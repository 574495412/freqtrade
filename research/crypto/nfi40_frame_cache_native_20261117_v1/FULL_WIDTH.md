# Full-width storage benchmark

The separately frozen full-width stage completed with exit code 0 (supervisor session 43075; worker PID 75246). All 180 native 1,000-row slice comparisons passed. This technical result supports a bounded replay parity experiment; it does not admit replacement of the running original NFI account controller or establish any strategy return.

The original frozen configuration retains its 40-pair context. Only BTC base data and the NFI informative data needed for BTC were loaded through native interfaces. The original start/end contract and 800 startup candles produced **175,904 × 231** indicator rows/columns, then **175,904 × 237** after native signals. Dates run from 2024-12-29 05:20 UTC through 2026-08-31 23:55 UTC. No rows were forced to an assumed count and no columns were invented. Configuration/source/data verification plus indicators took 4.917 s; native signals took 0.327 s. No old cache pickle was loaded, and no Backtesting or Wallets object was constructed.

All six cache keys received the same existing BTC frame object. The legacy mappings subsequently loaded independent process-generated pickle frames. These keys are six synthetic aliases of one asset, not evidence about six actual assets or the full 40-coin working set. Ten consecutive native clock indices each queried all six keys, crossing a 4,096-row boundary after the first cycle. The exact validation covered values, numeric bits, dtype, index/columns classes, attributes, flags and frequency. Validation time is reported separately from cache-read time.

LRU4 incurred 60 full-frame loads and retained at most four frames. LRU6 incurred six loads and retained six. The native getter checks membership and then reads the value, so the mapping counters also contain 60/114 hits respectively; these are mapping accesses, not additional strategy queries. The block variant loaded 12 blocks, retained at most 12, and had no eviction in this particular workload. Its 32-block eviction correctness was separately tested in the sealed small-frame stage. LRU6's resident reads were faster than the block prototype, while blocks avoided most full-frame decompression. Neither observation proves which implementation is best for the whole native pipeline.

Legacy writing and eviction retain the original implementation, including whole-frame serialization for mutation checks. Its reader has instrumented IO layers and verifies this run's generated file SHA before loading. Counters measure actual bytes returned by the compressed/decompressed IO layers. Legacy guard reads add another 4,837,751,600 bytes for LRU4 and 483,775,160 for LRU6 beyond their decoder compressed payload; those guard reads are included in elapsed time. The block implementation hashes its compressed buffer in memory and also checks raw SHA. The extra legacy instrumentation and guard cost, mode order, operating-system caching/compression, and identical aliases limit direct extrapolation to production timing. Only one run was performed; no statistical speedup estimate is claimed.

The separate supervisor checked this new worker every 0.25 s against 3 GiB RSS and 1.5 GiB available system memory, with phase checks inside the worker. Peak sampled RSS was 2,046,967,808 bytes; process high-water RSS was 2,121,220,096 bytes. Minimum sampled available memory was 2,790,506,496 bytes. LRU6 was feasible in this workload, without relaxing the limits. Guard checks are sampled, not an operating-system hard allocation limit. The protocol also recorded a 2 GiB disk floor; that disk threshold was sampled externally (over 22 GB free), not continuously enforced by the supervisor code. This limitation is retained explicitly.

`full_width_protocol.json` and `full_width_freeze.json` were written before the worker started. The initial small repeated-frame result remains negative and sealed separately; this full-width result does not replace it. Strict all-rule Ruff checking of the prior prototype had outstanding assert/complexity/style findings; only fatal/static error checks were run for this new stage, so there is no repository-wide lint-pass claim. `full_width_artifact_manifest.json` seals this stage and the previous stage manifest without altering old records.

The running original 500-USDT controller was neither modified nor restarted. There were zero financial accounts, exchange orders, wallet computations or risk-policy changes in these probes. Historical monthly precision and rule-coverage gaps are unchanged. Next admission would require an independently frozen short native lifecycle parity replay, including actual strategy callbacks, cache APIs and matching behavior; full-window financial parity is still unproven.
