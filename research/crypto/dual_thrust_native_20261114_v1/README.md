## 原始方法与本地适配

读取 [QuantConnect 托管的 BTC 实现](https://www.quantconnect.com/terminal/cache/embedded_backtest_b1a65b7cdcbd0e5ba35370df12ea454a.html)，保存实际 HTML、两个源码块及 SHA。源码使用四个完整日线，区间为 `max(最高高−最低收, 最高收−最低低)`，上下系数均为 0.5。**其锚是刚完成那根日线的开盘价**，不是新一天开盘价。小时价格触及上轨续发 365 日多头意图，严格跌破下轨取消，中间保留意图；未根据本地结果改成更常见的当天开盘锚点。

[旧通用教程](https://www.quantconnect.com/research/15258/dual-thrust-trading-algorithm/)的文字/内嵌示例与该 BTC 代码有差异，旧例还暴露过仅用下轨的条件问题。这里只把实际捕获的 BTC 源码作为规则来源，不把搜索摘要或旧示例混进当前规则，也不采用作者平台的收益为本地证据。

源账户为 GDAX、BTCUSD 现货现金、分钟数据与 LEAN insight/组合模型。本地固定使用 Binance BTC/USDT 永续、UTC 日历、完成小时线、原生 5 分钟细节回放、1 倍逐仓和最多一仓。使用原生 99% 可用资金首次建仓并保留实际数量到退出，没有复制源组合模型可能随新 insight 再平衡的行为。**这是明确的本地适配，不是源平台完整现金账户复现。**

资金窗口开始时为空仓；预热不会建立资金头寸。正常买卖不在 00/08/16 资金费时点执行，保留状态到下一允许小时；原生止损等生命周期规则仍生效。SMA 对照只用上一个完整日线的 10/20 均线状态，持有对照在第一个允许时点建仓，账户、成本、数据、估值及资金费规则一致。

这些是时间序列状态策略与资金配置研究，不是横截面新因子筛选。没有新增 Registry 定义、factor_analysis 或 Vibe bench，也不把相近价格趋势规则称为已证明独立的两个 alpha。
