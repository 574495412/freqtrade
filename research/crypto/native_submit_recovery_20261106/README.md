# 提交回执未知的原生订单恢复

## 首次入场

`query_initial_entry` 用原 client ID 查询订单并保存原始回执。`recover_initial_entry` 从已登记的因子决策、市场规则和原请求恢复原生 Trade/Order。恢复使用 Freqtrade 的原生 Order 解析、止损初始化和订单重算。若原生记录已提交，则比对原提交回执和本地字段，复用同一个持仓身份。

恢复写入前记录预期的原生状态。重试核对写入前后的已知状态，随后按来源查询继续处理累计成交。首次入场的原风险预留一直保留到完整账户对账。查询缺少成交时间时，部分成交终态恢复使用独立成交事件的时间和费用。

全成交沿用注册驱动的账户观察。部分成交后终止通过 `reconcile_recovered_terminal_fill` 应用原生 after-fill 并核对持仓、费用和余额。无本地持仓的零成交终态通过 `reconcile_zero_initial` 对账后释放预留。

本增量覆盖的回放包括原提交确认丢失、恢复提交确认丢失、查询累计成交增加、部分撤单后的检查点中断和错误余额后的新观察。已有空 Trade 的零成交清理，以及原提交中的填单日期缺失且原生已使用本地时间的恢复，仍需单独处理。

本轮 10 项合成隔离检查通过。源码哈希、四次回放日志和 145 个冻结金融输入的核验见 `entry_verification.json`。

## 退出

本增量处理本地已保存退出意图、交易所查询已返回订单，但原生 Order 记录缺失或提交确认丢失的情况。所有传输均为禁用网络的合成本地回放，不认证真实交易所状态。

`query_and_recover_exit` 通过已注册驱动的观察范围，使用原稳定 client ID 进行实际 CCXT GET 构造；取得 venue ID 后沿用原控制器的查询。`recover_exit_binding` 校验原请求、订单身份、累计成交和回执新鲜度后，使用官方 `Order.parse_from_ccxt_object` / `update_from_ccxt_object` 恢复真实 SQLite 记录。它不再次 POST，不调用成交财务回调，也不据请求内容虚构交易所响应。

恢复意图先于原生写入持久化。每一步记录写入前的原生记录、期望响应及已确认的写入后记录；重启后识别写入前后任一已知状态。若后续查询的累计成交增加，先核对前一步，再登记新步骤。任何持仓财务字段、其他订单、归属或费用的不明变化均拒绝覆盖。入场权限保持关闭，直到完整账户对账恢复。

零成交撤单保持官方解析出的真实终态，准备原生撤单清理日志；没有将其伪造为 OPEN。正成交仍要求原有完整费用、资金费、余额、持仓与 after-fill 证据后，才计入原生持仓和收益。
