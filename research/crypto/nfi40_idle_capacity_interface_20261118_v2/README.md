## 已实现的控制与验证

`NFIIdleCapacityDisabled.py` 是本地研究扩展，继承 SHA 固定的 NFI X8 `v18.0.146`；不是上游官方组合功能。它只增加构造入口保护：必须显式辅助关闭、回测研究模式，禁止用 `available_capital` 伪装共享分配器。26个包括原策略及父接口的回调函数对象保持直接继承，不改 NFI 代码、数字/空格入场标签、订单标签或交易自定义数据，也不注入头肩信号。由官方 `StrategyResolver` 实际加载成功，保持5m、LIMIT和800预热。

`CompletedIntentCalendar.py` 只保存原 NFI 输出的日期、入退场方向标志和原始标签；不保存 OHLC、钱包、接受结果或收益。它尚未接入辅助关闭控制。未来启用版本可在原 `populate_entry_trend` 与 `populate_exit_trend` 完成后，通过支持的回调捕获原始信号；当前时刻T只查精确的T−5m，40币缺任一币或该时点即拒绝辅助，不退回旧行。方向冲突规则已对照官方 `check_for_trade_entry` 全16种二元组合；40币合成未来扰动不改变当前快照。它不是账户或撮合模拟器。

实际验证分组：

- 26个回调函数身份完全继承；官方 StrategyResolver 与原 NFI 构造；辅助开启、未显式关闭、dry-run运行模式、available_capital 四种不准入情况拒绝。
- 原标签 `"1 2 "`、`"61 "`、`"501 502 "` 原样经过真实 NFI 入场确认、仓位函数和1倍杠杆函数；退出信号向量保留标签字节。
- 对真实 NFI `order_filled` 调用3组纯参数对象，比较首次入场系统版本及 derisk/grind 自定义数据；真实超时和回测 bot_loop 回调原样委托。**这些不是原生订单成交或完整 DCA/部分退出验证。**
- 真实原生信号移位/截断方法、真实 DataProvider 分币种切片滞后、40币只读日历/未来扰动/缺失拒绝、16种原生方向冲突。

595个官方 vendor 文件逐一匹配，进程 session72265 实际 exit0，峰值RSS420,020,224字节。没有新金融输出。真实完整指标与入场信号生成、DCA/部分退出、成交、资金费、现金和14,592小时账户一致性尚未运行；函数继承及这些对象案例不能替代它们。策略名称/导出元数据也会不同，应与未来账户经济一致性分开核对。

## 已核定的真实时钟

官方 `Backtesting._get_ohlcv_as_lists` 先缓存未移位的信号，再把信号和标签统一移位一行。小时确认在T收盘的头肩事件，应映射到5m行T−5m，再由原生移位到T。不得自行再次移位。

`time_pair_generator` 在更新当前各币 DataProvider 的 max_index **之前**调用 `bot_loop_start(T)`。因此在该回调读取 DP 最后一行通常仍是上一轮；首轮甚至为空。对象案例实际显示，一个币更新后，另一币仍落后。不能把它当作全40币当前 NFI 机会集，也没有修改官方DP指针来假装可见。上述严格日期日历是候选解决方案，启用前仍须真实源集成验证。

原 NFI timerange 从2025-01-01 00:00开始，截断后移位并去首行，实际首执行时钟为 **00:05**。对象案例已确认：投射在前一天23:55的头肩00:00事件不会进入原执行列表；00:55投射则正确在01:00进入。保持该初始边界诊断，不把事件推迟、不偷偷提前 native_start。若以后改变共同启动边界，必须另冻完整 NFI 控制。

旧 pending LIMIT 在 `manage_open_orders` 中先检查超时/取消，再进入后面的成交尝试。原全局 entry3分钟/exit2分钟超时保留；在5m时钟上，未成交辅助入场应在下一根开始时取消，不能迟到成交或排队重试。

|---|---|---|

| bot_loop/当前意向 | 先原回调；不改变原全局交易查询 | 从原信号日历精确查全40的T−5m；未知即不准辅助 |

预算仍为 `max(0,min(B/6,(F-5B/6)/(1+2f)))`。`confirm_trade_entry` 在原生最小单额和数量精度调整后接收实际 amount/rate，须复核实际保证金与双边费用预算；这一真实钱包/最小单额路径尚未验证，不能拿纯公式当已通过。

原生有持仓币先处理，因此辅助可能先请求退出；只有实际成交和原生钱包更新才释放现金。不能保证原子抢占、全部NFI信号被接纳或未来DCA余额。其他币NFI可以使用真实尚余现金；同币同刻辅助关闭后禁止反向第二循环重入，随后只能用自己的新时点信号。NFI原函数仍会看到全局辅助交易、共享现金和名额；不得隐藏辅助来宣称 NFI 结果不变。

原生安全封装可吞回调异常，入场默认甚至为True。未来辅助路由须明确拒绝错误、记录policy error，并在账户运行器验证/中止任何错误；仅抛异常不足以闭锁。辅助关闭控制仍保持原NFI行为，其完整账户回放必须独立完成。

## 无法保证项与最小原生扩展边界

按原预注册的**非原子优先级**，只读信号日历可避免依赖错误的DP当前视图，支持接口具备后续实现路径。此次未修改官方循环或钱包。如果要求不使用日历而直接得到全币当前意向，最小改动应归 `time_pair_generator`/DataProvider 的全币已完成意向阶段；如果要求“必定先全部退出、释放资金后再让NFI进场”，需要原生调度器显式退出→实际成交→钱包更新→入场阶段，会改变撮合次序，不能用IStrategy或虚拟资金代替。两者均未实施，也不是本阶段准入条件的暗中放宽。

每来源不同 MARKET/LIMIT 需要另一个原生订单类型接口，未选择；本方案保留NFI LIMIT并单独审核辅助 LIMIT 对照。历史 operation 暂停、改单/撤单/成交约束必须由所属原生交易所/订单生命周期实现并核验，策略意向本身不能证明。完整历史规则、旧整月精度启发式、AXS/TRB资金费未知以及多次成交归属限制继续保留。
