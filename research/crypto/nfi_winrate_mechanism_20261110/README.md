# NFI高胜率的成因与问题清单

结论：高胜率描述的是经过持有、退出和仓位管理后自然结束的交易周期。
它包含明显的盈利/亏损退出不对称，不能解释成下一小时方向判断有99%准确率，
也不能单靠它判断安全或是否过拟合。源码与流水共同支持这一结构；
各项机制分别贡献多少胜率，尚未做原生消融试验，不能把相关性写成因果比例。

本轮只诊断既有Freqtrade原生结果，未生成新的账户收益、调参、下单或改动运行策略。
上游NFI固定提交的原始文件已再次从GitHub校验，与实际执行的文件SHA256一致。
本地首仓1.25倍、历史选币/时钟、资金上限、估值/存储扩展单独标注，不称上游原样功能。

## 一、高胜率具体由什么形成

### 1. 盈利较快确认，亏损较慢结束

同一窗口：2026-01-01至2026-11-09 05:00 UTC，每账户初始100U、交易预算99U。
合约3倍、12仓、每侧8bps；现货36币、6仓、每侧13bps。均以原生成交扣费损益为准。

| 指标 | 合约原币名黑名单 | 合约不排除具体币名 | 现货36币 |
|---|---:|---:|---:|
| 自然盈利/自然结束周期 | 308/309 | 357/361 | 50/53 |
| 自然平仓胜率 | 99.68% | 98.89% | 94.34% |
| 盈利周期持仓中位数 | 5.67小时 | 5.17小时 | 4.04小时 |
| 自然亏损周期平均持仓 | 17.94天 | 13.80天 | 19.31天 |
| 平均盈利周期净赚 | 0.4424U | 0.4450U | 0.4899U |
| 平均自然亏损周期净亏 | 1.1452U | 5.5160U | 1.3843U |
| 一次平均亏损抵消平均盈利次数 | 2.59 | 12.39 | 2.83 |
| 期末仍未自然结束周期 | 3 | 3 | 1 |
| 未结束周期合计标记损益 | -15.4166U | -15.4166U | -0.4731U |
| 包含原生窗口末强制平仓后的胜率 | 98.72% | 98.08% | 92.59% |

自然亏损只有1/4/3个，平均亏损不能视为已可靠估计的未来尾损规模。
盈利中位数与亏损平均数是明确不同的统计量；亏损案例逐笔保留在evidence.json和CSV中。
例如现货SAND、LINK亏损周期持有约21.78、20.66天，AXS约15.50天；
不排除具体币名的合约ALICE亏损约9.59U，相当于该组约21.55个平均盈利周期。

普通盈利退出中有明确的正利润门槛。亏损时若未满足异常退出条件，会继续管理/等待；
因此最终关闭的周期倾向盈利，少数亏损和资金占用集中在持有时间长的周期。
这不证明每个入场都有独立预测优势，也不意味着所有盈利都靠扛单。

### 2. 交易周期、订单和入场预测是不同口径

一次周期可能有多次买入、部分卖出和再买入；胜率按整个周期最终净损益计数，
不是每个订单、每次加仓或每个信号各算一次成功。下面是同批实际原生首笔成交，
在固定时距后用真实5m OPEN价格测量的有利方向比例：

| 辅助价格标签 | 合约原黑名单（312周期） | 合约无币名排除（364周期） | 现货（54周期） |
|---|---:|---:|---:|
| 入场1小时后方向有利 | 52.24% | 54.12% | 68.52% |
| 入场4小时后方向有利 | 58.01% | 54.67% | 62.96% |
| 入场24小时后方向有利 | 55.13% | 54.40% | 64.81% |

这些价格标签未扣费、不模拟持仓和退出，不是另一套策略收益或因子IC。
它们仅解释为什么自然平仓胜率不能当方向预测准确率；
不能用某个固定时距的比例判定跨周期策略没有价值。
样本也受原策略资金/入场路径选择，且并非相互独立的试验。
原黑名单合约309个自然周期仅有265个不同入场时点，71个周期与其他周期同时入场。

### 3. 加仓有影响，但不能把高胜率全部归因于加仓

| 原生周期/成交指标 | 合约原黑名单 | 合约无币名排除 | 现货 |
|---|---:|---:|---:|
| 盈利周期中完全没有加仓 | 277/308 | 314/357 | 45/50 |
| 全部追加成交次数 | 51 | 100 | 8 |
| 其中追加价格比首笔更不利于原方向 | 48 | 97 | 8 |
| 单周期最多累计入场成交数（含首笔） | 9 | 16 | 3 |

多数盈利周期没有追加。追加可以改变成本、曝险和退出路径，但它的净收益贡献、
去掉追加后还剩多少胜率，必须用原生消融验证，不能从这张表直接推算。
累计入场次数可包含减仓后的再买入，不等于同时持有这些订单，更不等于本金翻倍的马丁。

### 4. 未结束亏损不进自然胜率分母，但已进入净值

原黑名单合约期末3个周期为APT、JUP、PHA，持有约10.37、10.37、16.45天。
未结束周期合计损益约-15.42U，相当于约34.84个该组合的平均盈利周期。
PHA单周期9次入场、窗口末原生结算净亏约7.96U。

这里的“未结束周期标记损益”包含该周期此前的部分卖出现金流、剩余持仓标记价值、
费用储备及原生资金费，不严格等同于交易所只针对剩余仓位展示的未实现盈亏。
已自然结束周期损益+未结束周期标记损益，与原生完整净值的最终损益核对一致。
之前将其简称为“浮亏”不够精确，但不存在从净值中漏扣该部分损失的情况。

把末期强制结算计入后胜率仍高；分母遗漏并不能解释全部高胜率。
它主要提醒我们：自然胜率没有表达完整的未结束风险。

## 二、已确认的策略风险与验证缺口

| 优先级 | 具体问题 | 证据与影响 |
|---|---|---|
| P0 | 常规止损退出被否决 | confirm_trade_exit会否决stop_loss/trailing_stop_loss；强制退出及强平另有处理，不能只改stoploss数值就假设保护生效 |
| P0 | 当前v4通用doom固定阈值止损关闭 | system_v4_stops_enable=False；bad-trade退出与部分减仓仍存在，但不等于统一硬止损 |
| P0 | 异常亏损退出是多个条件联合触发 | 结构退出要求方向化日线EMA50/200差≤-35%且首价不利变动≥25%；陈旧仓退出要求年龄≥14天、不利变动≥10%、14日平均日波幅<7%，14天不是无条件最长持仓期限 |
| P0 | 未启用交易所保护止损 | order_types.stoploss_on_exchange=False，风险管理依赖进程、行情、API和退出订单成交；上一轮合约已实际观察到418，心跳不等于退出链路可用 |
| P1 | 追加上限与亏损上限不是一回事 | 原生全局max_entry_position_adjustment=-1；内部仍有分支/在途限制，99U预算也有效，但没有统一周期追加次数上限；不能称无限本金，也不能据99U预算保证账户回撤 |
| P1 | 30%是历史筛选门槛 | 当前没有因此自动生成“净值亏30%立即平仓”的规则；5m标记回撤也不是所有盘中时刻的最坏损失 |
| P1 | 费用会改变策略路径 | 原1000U同窗口从8到15bps，收益201.24%→145.56%、加仓63→142；不是仅从固定成交扣一个费用差。当前100U更高成本完整重跑尚缺，不能直接套用旧1000U压力结果 |
| P1 | 事后选币与反复筛选影响可信度 | 无币名排除组新增的BB/PORTAL/ALICE自然亏损周期均受旧名单排除；自然亏损均值从1.15U升至5.52U。去掉名单仍缺完整历史退市币/市场规则，也不是独立样本外 |
| P1 | 真实成交证据不足 | 上一轮现货/合约核对仍零成交，无法确认真实滑点、费用、重复追加防护和成交后通知一致性 |
| P2 | 当前100U合同缺统一简单基准及消融 | 还不能仅凭正收益确认复杂信号、首仓增强、加减仓分别提供多少超额收益 |

上述源码是固定上游版本的行为，属于设计取舍/风险缺口，不能全部称为程序错误。
`exit_profit_only=False`，且流水有真实自然亏损退出，因此也不能说“策略绝不止损”。
信号192有单独亏损退出，但本次三组均无192周期，不能用它代表总体保护。
止损在杠杆模式下表达的是资金风险比例，不能把-0.99简单解释为币价还能跌99%。

## 三、一个具体的退出门槛例子

按原生输入和相同日线指标公式重建窗口末的风险输入：
PHA的EMA50/200差约+13.82%，14日平均日波幅约10.16%；
前者未达到≤-35%，后者未达到<7%。这两条异常退出分支在该时点的条件均不满足。
APT、JUP在末时点也不满足这两条组合门槛。

这说明“已经持有很久/价格大幅不利”不自动等于会退出。
这里只复核门槛输入，不把末时点快照冒充整个custom_exit回放或对全部未退出原因的证明；
还存在其他退出/减仓分支，完整控制流的个案追踪应另行验证。

## 四、整改与验证顺序

1. 先验证可靠风险退出：止损/紧急退出不被错误否决，保护委托能在交易所真实生效，
   行情/API失效时状态可核对。风险参数变更要作为新合同，不能直接把旧收益当新策略收益。
2. 冻结同资金、币池、费用的原生消融：原规则、明确的周期追加限制、明确的持仓/亏损退出规则。
   不预先假定这些规则会提高收益或继续保持高胜率；失败也必须保留。
3. 先比较净收益、完整标记/更细粒度风险、最坏周期损失、占用时间和费用压力，再看胜率。
4. 今年已反复观察的数据归为开发证据。独立验证需要参数先冻结后的新数据，
   并补齐历史成员资格与同风险简单基准，不能靠重复跑今年获得独立样本外。
