# Hash Ribbons：链上时钟未通过准入，未运行资金账户

**本地冻结候选在数据准入阶段停止。计划 28 个原生账户，实际资金账户 0、因子分析 0、新接受因子 0，收益保持未知。** 这不是 Hash Ribbons 经济机制的收益拒绝，也没有证明原作者策略亏损。

目标窗口保持 **2025-01-01 00:00～2026-08-31 23:00 UTC**，14,592 个小时决策点。未缩窗口、延长 72 小时陈旧门槛或把未知时点补成空仓。没有订单、部署、运行服务变化、提交或推送。

## 来源与数据可知时点

[Capriole 原作者说明](https://capriole.com/capriole-newsletter-issue-23)明确 Hash Ribbons 只提供买入信号，退出需要另行确定。因此冻结方案中的长期/空仓状态和失效退出是本地假设，不是原作者完整账户复现；没有把未来周期高点收益作为可执行退出。

[Coin Metrics 完成时间定义](https://docs.coinmetrics.io/network-data/network-data-overview/availability/asseteodcompletiontime)描述该资产最后一个日度指标算完的时间，单位为 epoch 秒；计算从 UTC 零点开始。日线日期不是全部值当时已经算完的证明，完成时间也不是特定修订版本的首次公开记录。

固定 [coinmetrics/data](https://github.com/coinmetrics/data/tree/f1a36afb962731c387bb03982758ab0103063da5) 提交 `f1a36afb962731c387bb03982758ab0103063da5`，提交时间为 2026-05-24；已读取 README、生成脚本、许可证和 BTC CSV。该库当前快照没有完整覆盖目标窗口末端，不能仅凭 README 的每日更新说明假定它持续更新。许可为 CC BY-NC 4.0，不是 MIT。

当前 API 捕获 2024-10-01～2026-08-31 的 **700 个日度 HashRate 值**。与固定 GitHub 快照重叠的 **600 个值均按原始 Decimal 精确相同**；这是快照间一致性，不是当年首次公开或更早未修订的证明。

## 保留的两次输入失败

原单快照方案因 **2026-04-02 的 AssetEODCompletionTime 缺失**停止；定向重查仍缺失。旧 GitHub 快照保留了同一天完全相同的原始哈希率及提供者报告的完成时间。v002 在任何信号状态或财务结果生成前明确修订输入合同：只在原始值精确相等时使用实际提供的时间，取所有已知时间的较晚者；保留当前空值和两个来源字段，绝不猜邻日时间或替换不同数值。

即便如此，仍未通过冻结合同：

|可知时钟模型|不可准入小时 / 14,592|原因|
|---|---:|---|
|默认实际捕获时间|14,592 / 14,592（100%）|快照实际捕获在 2026 年 11 月，晚于评估窗口|
|显式完成时间模型|46 / 14,592（约 0.315%）|2025-05-04 01:00～05-05 22:00，输入年龄超过 72 小时，最高 118 小时|
|完成时间另延迟 24 小时|70 / 14,592（约 0.480%）|2025-05-04 01:00～05-06 22:00，最高 142 小时|

均线特征需要其整个 60 日输入窗口都已完成，不只检查最后一天。当前快照中，全部 608 个日历日的前一日特征都不能简单假设在次日 01:00 已可用。这里按小时 as-of 连接，同时拒绝陈旧输入；未将日线标签直接连接交易日，也不让晚到的旧观察把当前状态倒退。

上述完成模型本来就只属于明确的回溯条件模型，不认证历史版本；现在连其数值完整性也未通过，因此停止整个链上账户矩阵，包括匹配时钟对照。没有只跑独立价格对照，再将其称为链上策略证据。

## 原生入口与正确性证据

`freqtrade/data/onchain.py` 是本地数据合同扩展，并非上游已有链上模块。策略入口副本 `OnchainInputs.py` 与其字节相同。原生引擎固定为 `c051e9065c5b677f03817dd1f83cb980af1ed684`，重新核对 **595 个源文件**。

26 项输入检查通过，包括原始值精确匹配、空值保留、时间单位、完整日历、全部 60 日的完成时钟、边界/延迟、默认捕获模式、报价比例不变性及四个日期的未来扰动/截断。实际数据的 641 个完整特征窗口另与标量均值和最大时钟核对。

实际调用 **StrategyResolver、IStrategy.bot_start 和 DataProvider** 的六次检查均按预期在状态与账户建立前拒绝：默认模型一次、零延迟三次、24 小时延迟两次。它们是原生输入入口检查，不是六个回测。`v002/rejection_audit.json` 保留逐项原因与缺口区间。

技术失败原样保留：合成夹具最初误将 pandas 3 的微秒整数按纳秒换算；修正夹具后 26 项通过，生产规则不变。原生检查壳最初继承了旧候选的无时区结束日期，随后缺少 `Path` 类型；均在输入检查阶段修正，未改变财务窗口或产生资金绩效。初始单快照失败、v1 文件、v002 修订及全部失败日志仍在。

## 下一步边界

当前源数据不足以支持这套冻结账户。若未来取得真正的历史发布版本或独立完整时间证据，应另立输入合同并保留本次失败；不能把现时修订值或更长陈旧容忍度当作原方案通过。下一研究转向独立来源的小时级 BTC 区间突破，另立合同，不修改本候选的均线、方向、退出、时限或结果。
