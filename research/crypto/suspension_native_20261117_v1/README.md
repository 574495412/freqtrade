# 加密原生订单操作暂停与旧挂单撮合

本批完成Configuration→本地原生Backtesting.start→原生结果ZIP的两个合成工程账户，并保留两个预期拒绝案例。独立读取实际成交、费用、资金费和终值现金，对账通过。它们不是历史策略收益或新增alpha；原40币完整规则仍未准入，本批没有新的更高收益结论。

## 源数据改变了实现方向

此前的[币安公告](https://www.binance.com/en/support/announcement/detail/bb0c704f3ca344c7a8741c551dd624ce)禁止CRV/GALA各一分钟内的新单、撤单和改单，并保留旧挂单原精度。不能据此直接假设整个分钟没有撮合。

通过已连接Binance公开接口取得两币各六根原始1m K线。CRV在2026-04-29 06:30UTC分钟记10笔成交，GALA在06:40UTC分钟记11笔。逐笔接口拒绝这两个历史时点，错误为只允许最近两天；失败回执保留。随后按[Binance官方公开数据说明](https://github.com/binance/binance-public-data/blob/master/README.md)取得两份日aggTrades及两份日1m ZIP和公开CHECKSUM，四份ZIP均通过SHA/CRC核对。

独立Decimal核对归档与连接器：CRV分钟9条聚合记录、10笔底层成交，发生于06:30:06.580～48.174；GALA分钟10条聚合记录、11笔底层成交，发生于06:40:00.256～35.842。价格OHLC、基础量、成交数一致。每份日K线1440行、时钟连续。不可删除该分钟、补零成交或把整分钟统一设为停止撮合。

这些是同一交易所的当前归档/API版本，不是不同结算权威；不认证历史first-seen、精确撮合规则切换时刻或假设客户挂单的实际成交。公告中的操作禁令与归档中的市场成交并存，历史客户订单的具体处理仍需进一步证据。

## 原生扩展与完整工程运行

新增本地OrderOperationMixin，继承上一批日期价格接口及原生Backtesting，不替换钱包、订单撮合、资金费或结算引擎。默认运行器不选择它。配置必须为5m策略、真实1m细节；原始文件在关闭补K线的读取下必须覆盖事件所涉及的整个5m区间。

冻结窗口将新单/撤单/改单禁止，与旧挂单撮合政策分开。已知continue、已知stop和unknown是不同合同；unknown遇到可达旧挂单直接拒绝，不选择更好收益的假设。新单在恢复后的原生分钟重新处理，旧挂单保留原订单价格；费用和资金费沿用原生流程。当前接口限上一批已声明的离线Binance逐仓、限价研究合同。

以下全部使用FAKEONE/FAKETWO、1000USDT、明确合成OHLC及规则，匹配政策由夹具声明，不能映射为真实CRV/GALA账户：

|已冻结案例|实际原生结果|
|---|---|
|continue|完整start及ZIP；旧退出单06:00成交，新入场单06:01成交|
|stop|完整start及ZIP；旧退出单06:02成交，新入场单06:01成交|
|unknown|可达旧挂单触发未知撮合合同异常，无完成ZIP|
|missing_detail|原生虽可补K线，原始1m缺口仍被拒绝，无完成ZIP|

两个完成账户中，旧订单价格103.005跨越新0.01网格仍被保留，新订单价格100.01按恢复后精度生成。独立从实际ZIP重算成交现金、双边费用及06UTC资金费：第一笔应付0.1USDT，第二笔在06:01后开仓，不收06UTC费用；终值与原生钱包一致。两个夹具碰巧同终值，成交时刻不同，未将这点计为利润改善，也不声称结果证明真实暂停时撮合政策。

## 失败与证据范围

首个continue原生start已经完成并留下ZIP，但辅助JSON导出遇到Timestamp序列化异常，初始failure.json把native_start_completed错误写为false。原日志、ZIP及修正回执保留。另发现初始清单遗漏运行器SHA，未补造它。修正仅辅助序列化/生产者回执，另目录进行有运行器SHA的完整复验，成交与首个ZIP逐项相同。复验前还有一个ROOT导入NameError，发生在原生启动前，日志保留；未计作原生回测。四个有回执的工程案例均已观察到进程终态。

旧日期精度模块、原生主模块和上一批封存文件未改；固定官方vendor的595文件核对不变。OrderOperationMixin是本地扩展，不能称为官方上游支持。原生合成运行证明接口和订单生命周期在这些夹具上的行为，仍不证明因子效力、40币真实完整账户、更高可比收益、纸盘或实盘表现。

后续须继续取得40币完整日期规则及暂停期间的客户挂单合同，结合未完成的数量/名义金额等规则准入，再以原资本、费用、窗口、策略及隔离缓存运行真正历史账户。每个新账户重新核查未知资金费暴露，完整净值独立审核后才比较新因子和实际资金分配组合。
