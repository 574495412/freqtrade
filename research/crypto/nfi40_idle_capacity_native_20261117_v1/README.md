# 原40币 NFI 闲置资金利用假设预注册

本批冻结一个尚未实现、尚未获准启动资金回测的组合政策：单个原生 **1,000 USDT** 钱包以原 X8 为主，头肩辅助策略仅在 NFI 空仓时借用部分现金。它由已经看过的旧 1,000 USDT 账户容量及已准入源事件启发；不是新头肩收益公布后的挽救，也不宣称独立样本外。此研究未读取并行 500 USDT 钱包结果或任何新的头肩市场收益。

## 冻结的五项政策

1. 原40币顺序、1,000 USDT共享钱包、逐仓1倍、总6名额、5分钟原生执行、15/8 bp与完整共同窗口不变。最多一笔辅助；有NFI持仓/挂单、已有辅助、或任何币当前已知有效方向NFI信号时，拒绝新的辅助。多辅助事件按原币序选择；只在原小时确认后的精确下一开盘尝试，不排队、不延后重试，自终止事件保留但不入场。
2. 令B为原生`get_total_stake_amount()`、F为原生`get_available_stake_amount()`，辅助本金最多B/6，保留5B/6及双边费用预算。每边费用f下申请`max(0,min(B/6,(F-5B/6)/(1+2f)))`。原生最小单额与数量精度调整后再检查；超限拒绝。此储备不保证未来所有DCA或资金费，禁止虚拟子钱包和假资本转移。
3. 任意NFI新信号或持仓出现，辅助请求完整抢占退出并记录独立原因，持续至原生实际成交。只有成交与钱包更新才能释放资金。拒绝同币同刻关闭后的反向二次循环重入；后续NFI须有自己的新时点信号。挂单、暂停、延迟、费用、资金费、错过的NFI信号与仓位改变全部保留，不能假定原子抢占。
4. 原NFI数字空格标签原样传递，`hs1_*`绑定辅助原事件，未知标签拒绝/独立政策错误退出。NFI退出、加减仓、成交、自定义数据和超时回调回到原函数；辅助不DCA、不部分退出，也不调用NFI交易回调。不修改固定NFI源码。
5. 不承诺NFI结果不变：实际现金、全局名额、同币排他、辅助盈亏与抢占费用都会影响主线。一个IStrategy只有一个主周期及全局订单类型；最小方案保留NFI的5m/limit，另行冻结头肩5m开盘limit适配。原1h/market头肩接口不等价。小时信号按原生合并规则映射到T−5m再由原生移位；源退出仍只读已完成小时close，原生灾难止损/强平单独保留。

## 资金验证门槛与两级结论

组合代码尚未实现，本文不准入任何组合资金回测。启动之前必须先完成：关闭辅助时与原NFI逐信号、标签、成交、DCA/部分退出、费用、资金费及完整账户的原生一致性；另行固定并完整审核头肩5m/limit单策略控制；真实原生生命周期测试覆盖资金储备、名额竞争、标签隔离、暂停抢占、同刻反向重入及因果时钟。正式组合只能由Configuration → 本地Backtesting.start → 实际ZIP/同一钱包产生，再独立核对完整成交、费用、资金费、现金和共同终点NAV，不能相加两条袖套收益。

第一级是明确限定的旧模型条件性工程/账户比较：保留旧整月OHLC精度启发式、历史规则有效/已知时钟缺口、币池存续可交易性未认证及OHLC/费用代理局限。AXS/TRB的2026-06-24 04UTC费率仍UNKNOWN；旧账户无暴露不能授权新账户继承零影响。本文并未批准第一级执行。

第二级是更严格的历史因果执行认证：须准入相关历史交易规则及资金费所有权/覆盖，再完成相同合同的完整原生控制与独立审核。第一级不能升级成第二级；当前没有认证的修正后历史收益。

`protocol.json`冻结完整政策、输入哈希与公式；`capacity_diagnostic.json`保存精确聚合和语义更正；`artifact_manifest.json`封存这三份文件。只读取旧账户字段和源事件元数据，未调用源收益函数，未启动账户、订单或部署。整体更高收益目标尚未完成。
