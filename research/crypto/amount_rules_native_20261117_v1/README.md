# 加密原生日期数量与最低名义额规则

本批扩展本地原生Backtesting的数量与最低名义额接口，完成三组新合成账户、两个预期拒绝案例，以及两组既有暂停案例的完整原生回归。五份实际原生ZIP核对通过，三个新完成账户的成交、费用、资金费和钱包终值独立重建一致。12项新单元案例加21项既有价格回归，共33项通过，包含原生做空下单数量路径。**没有新增40币历史策略账户、因子或组合收益证明，也没有修正后的NFI收益。**

## 修改及其目的

固定官方祖先为Freqtrade c051e9065c5b677f03817dd1f83cb980af1ed684，595份官方vendor源码未改。本批修改本地原生Backtesting，新增dated_amount_rules模块；它们属于本地扩展，不描述为上游已有功能。钱包、撮合、订单记录和资金费流程仍由原生实现执行。此前原生Trade工厂与其他未涉及方法的AST保持不变。

新增接口分别处理：日期数量精度、日期最低/最高stake、最终已舍入订单过滤、跨步长持仓核算及部分减仓后的剩余量。默认接口保留此前行为；未明确选择DatedAmountMixin的运行器不使用新规则。当前扩展要求离线Binance逐仓、1x、单位合约、限价研究合同。

发现并处理的关键路径：

- 首次入场、加仓及请求替换价之后，都按当时规则检查最终数量、数量网格和名义额。仅检查舍入前stake并不足够：54USDT的意图可能舍入成40USDT订单，低于51USDT门槛，因此本案例没有创建订单。
- 新订单的合法步长与Trade的持仓核算精度分开。若最初步长为1、后按0.1加仓，沿用旧Trade数量精度会截掉新成交。扩展只用此前核算网格及当前已知订单步长计算十进制公约网格，不从未来规则书挑最小步长。实际序列`1+0.6-1.2-0.4`完整保留。
- 部分减仓使用当时数量步长。仅在规则明确声明只减仓最低名义额豁免时，允许保留及关闭低于开仓名义额门槛的余额；数量最小值和网格仍分别检查。这里的只减仓是模拟Trade退出语义，不是已取得交易所订单标志或接受回执。
- 已被原生接受的旧挂单不在成交时重新套用新数量过滤器。新下单与旧挂单保留分开，未改旧Order数量。
- 规则缺口、晚知、重叠、无效数值、合同漂移拒绝；数量网格非零偏移目前拒绝，不冒充支持。规则变粗后无法按当前合法数量关闭的残仓中止账户，不清零、不偷换旧Order当作强制退出。

## 真实执行的合成案例

全部使用FAKEONE、固定人工价格及明确规则，按Configuration→本地原生Backtesting.start→原生结果ZIP执行；不代表任何真实币种策略收益。

|冻结案例|实际结果|
|---|---|
|fine_DCA|完整；入场1、加仓0.6、部分退出1.2、全退0.4，资金费按当时1单位计入|
|notional_fall|完整；同一60USDT入场意图在旧门槛下拒绝，在新日期门槛下入场|
|post_round|完整空仓账户；最终40USDT订单低于51门槛，订单未创建|
|coarse_dust|撮合阶段拒绝不支持的关闭数量，失败档仍保留0.6持仓|
|unknown|日期规则缺失，完整窗口预检在start之前拒绝，无资金回测ZIP|
|既有continue/stop|两份完整原生回归；实际ZIP的逐笔交易与钱包终值均与此前封存ZIP相同|

独立审计直接读取ZIP的原生订单，按十进制现金收付、双边费率及冻结人工资金费重算。完整小时边界开仓按本版本原生Binance资金费合同计入，未冒称交易所实际到账。三个新完成账户分别为有成本亏损或空仓，结果均保留，未改信号、时刻、规则或成本以挑选更高收益。

## 来源与保留记录

阅读了[币安USD-M过滤器原文](https://developers.binance.com/en/docs/products/derivatives-trading-usds-futures/common-definition)中LOT_SIZE、MARKET_LOT_SIZE和MIN_NOTIONAL段落：数量最小/最大值、步长和最低名义额是不同字段，文档数量条件使用`(quantity-minQty)%stepSize`。本扩展仅支持最小数量与零网格对齐的合同；其他偏移拒绝。[合约规格说明](https://www.binance.com/en-AE/support/faq/detail/360033161972)说明只减仓最低名义额豁免，仍需具体历史规则来源。当前网页解释不认证整个历史窗口。未引入新的社媒策略规则、视频观看或字幕准入。
