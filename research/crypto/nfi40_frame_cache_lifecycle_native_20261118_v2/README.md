# Terminal resource-gate correction, held technical producer v2

This is a separate technical correction to the sealed 20261117 v1 producer. The old producer, tests, manifests and failure findings remain unchanged. `plan.json`, `admission.py`, `receipt_contract.py` and `preparation_freeze.json` are byte-identical copies of their old versions; original source, capital, fees, leverage, pair order, slots, dates and predecessor success requirements are unchanged. No execution release exists and no native financial account is started here.

The v1 bug is explicit: `Resources.finish()` discarded the final `sample.failed` after stopping its monitor. The last sample could first exceed the budget while the worker still exited 0; the controller did not bind or validate the resource file. V2 writes the final resource receipt, checks final/current and historical sampled RSS/available-memory/disk/time bounds, and raises on any failure or a still-running monitor. This final check runs after export and cleanup. A failure preserves both `resources.json` and `terminal_resource_failure.json` and cancels a pending successful return.

The controller now binds both native-output and resource SHA256 to the actual `Popen.wait` process receipt. Before accepting a worker it verifies schema, PID, final-check flags and all resource limits independently. A producer success flag does not override an exceeded bound. The resource receipt is performance evidence and is not compared numerically between the two storage modes.

V2 also records actual native callback slice start/stop positions and whether a read crosses a 4096-row boundary. It reads only the provider's existing slice index and the recorded length at native cache assignment; it never changes the getter, source data or matching path. After exact observed native parity, a separate technical gate requires at least one real callback crossing and actual candidate-cache eviction at its fixed 32-block capacity. Missing coverage preserves `observed_native_parity.json` but stops admission; no wider window or retry is selected.

Even with these gates passed, the claim is limited to **observed paths in the original fixed short window**. The separate 9003-row/8192-boundary synthetic native matching producer and full-window replay are still unimplemented or unexecuted. `complete_cache_lifecycle_certified` and `execution_replacement_admitted` remain false. This version does not convert a short replay into complete cache lifecycle certification.

The old NFI2 + HS4 success-only predecessor gate remains mandatory, including the known circular dependency if a predecessor really fails. Technical recovery from a failed predecessor is still NOT_IMPLEMENTED and needs a separately frozen version with actual controller/worker terminal receipts, bound process identities, shared-lock admission and explicit root release. No elapsed-time or lock-file inference bypasses it.

Only static checks, pure resource/receipt objects and detached official DataProvider/LocalTrade/Order fixtures are permitted now. Those tests do not execute `Backtesting.start`, acquire the financial worker lock or replace any active runner. The new resource/cross-block gates require independent review before any future root release.
