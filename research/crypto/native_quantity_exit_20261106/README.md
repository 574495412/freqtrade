# 缺估值数量退出：隔离原生适配 v1

此增量实现已触发 RD1 全量退出时的数量型执行路径。现金、标记价格和最新资金费覆盖可以未知；持仓与订单清单、原生数据库绑定、已知财务事件及独立执行卖价仍须核对。缺估值本身不会创建清仓指令，也不会恢复入场许可。

现货临时钱包只提供明确的基础币可用/占用/总量，读取未知现金会报错；合约使用官方原生 reduceOnly 路径，不构造零未实现盈亏。两者均调用实际 `FreqtradeBot.execute_trade_exit`、原生 Order/Trade SQLite 持久化与 CCXT 请求构造器，网络由测试夹具禁用。退出意图先落盘，丢失回执保持未知，不重复 POST；估值恢复后，继续沿用原生完整账户、费用和成交对账。

`QuantityResearchDriver` 在新隔离账户创建时登记独立策略版本；旧驱动不能静默升级或重新打开它。数量观察游标持久化在退出日志，后续完整账户必须更新于该观察；驱动之外的直接调用被拒绝。原金融实验的冻结源码没有改动。

19 项合成检查通过，覆盖：

- 现货和合约缺现金/标记退出，以及完整账户恢复后的实际成交和费用核算。
- 已知资金费不被重置，缺失的新覆盖仍标记未知。
- 无原有清仓触发、缺失/过期卖价、不完整订单、陈旧订单清单、持仓不匹配和基础币被占用时拒绝提交。
- 钱包屏障/退出意图持久化失败、丢失回执后的重启防重，以及原生提交确认丢失后的已有订单绑定。
- 注册驱动的双持仓进入、数量退出、完整批次对账；旧驱动绕行和旧账户快照拒绝。

运行命令：

```sh
.venv-paper/bin/python -B -m unittest discover -s research/crypto/native_quantity_exit_20261106 -p 'test_quantity*.py' -v
```
